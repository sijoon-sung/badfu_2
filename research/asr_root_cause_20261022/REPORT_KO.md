# BadFU와 FUBA ASR 이상 원인 검증

**현재 FUBA 실행은 논문이 의도한 잠복 후 활성화를 재현하지 못했다.** 공개 코드를 실행했다는 사실과 논문의 공격 현상을 재현했다는 판단을 구분하지 않은 것이 핵심적인 검증 절차의 잘못이다. 반면 논문식 BadFU 5참여자 실행에서는 삭제 전 낮은 ASR과 위장 삭제 후 높은 ASR이 확인됐다. 서로 다른 보존 실행과 평가 조건을 한데 묶어 “계속 ASR 문제”라고 해석하면 원인을 놓친다.

## 실행별 판단

| 실행 | 관측 | 현재 판단 |
|---|---|---|
| BadFU 논문식 5참여자 일반 위장과 batch 32 | 전체 시험에서 ASR 16.133% → 99.989%, 정상 대조 1.533%; 정확도 88.23% → 88.15% | 논문의 활성화 방향과 일치. 논문 수치의 엄밀한 재현 완료는 아님 |
| BadFU 기존 6참여자 실행 | 별도 320장 평가에서 80.56% → 99.65% | 위장 효과가 약한 별도 조건. 잠복 공격 검증의 주 기준에서 제외 |
| FUBA 기존 원 MPI 실행 | 원래 시험 분할과 저자 함수로 삭제 전 ASR 98.180%; 정상 학습 모델도 같은 생성기에 95.007% | 잠복 재현 실패. 높은 ASR을 독성 학습의 증거로 해석할 수 없음 |
| FUBA 새 5시점 단축 언러닝 | 공격과 정상 대조 모두 정확도 약 11%; BN 통계만 보정해도 회복 안 됨 | 우리 변형 FU의 정상 기능 실패. 공격 활성화나 정화 성과로 사용하지 않음 |

BadFU 원문 Table I의 CIFAR-10 ResNet-18 값은 삭제 전 ASR 21.55%, 재학습 후 99.32%다. 논문도 삭제 전 ASR이 0인 상황을 제시한 것은 아니다. 정상 대조와 같은 수준의 완전 잠복이라는 뜻도 아니다. [원문 Table I와 평가 정의](https://arxiv.org/html/2508.15541v1#S7.SS1)

## 평가 구현 때문에 생긴 수치인가

**가설 한 줄: FUBA의 높은 삭제 전 ASR과 정상 모델 ASR은 저자 평가 함수로 바꾸면 사라진다.**

- 조건: 같은 저장 분류기 4개, 같은 삭제 전 생성기, 고정한 320장과 원 실행의 9,280장 시험 분할. 목표 클래스 8의 원래 표본을 분모에서 제외한다.
- 저자 `attack()` 함수 본문을 실제 실행 소스에서 추출해 그대로 실행했다. 분류기는 eval 모드, 생성기는 원 코드처럼 train 모드인 조건과 eval 모드인 조건을 구분했다. 원자료와 생성기는 DISLAB에 유지했다.
- 같은 조건에서 독립 집계식과 저자 함수의 ASR 오차는 최대 약 1.42×10⁻¹⁴%p였다.

| 원래 시험 자료 9,280장 중 비목표 8,352장 | 삭제 전 ASR | 정상 정확도 |
|---|---:|---:|
| FUBA 공격 학습 모델 | 98.180% | 74.149% |
| FUBA 정상 학습 모델 | 95.007% | 75.313% |

공격 모델의 원 실행 로그 ASR 98.192%와 재평가 98.180%는 비목표 표본 한 장 차이다. 분류기 구성, 표본 수, 생성기 모드의 작은 차이로 98%라는 현상 전체를 설명할 수 없다. 정상 모델에는 같은 공격 실행의 삭제 전 생성기를 적용했다. 정상 모델이 생성기를 학습했거나 독성 데이터를 학습했다는 뜻은 아니다.

**결과: 가설 기각.** 현재 평가에서 높은 공격 반응은 실제로 존재한다. 이것만으로 논문과 다른 학습 결과의 원인이 모두 밝혀진 것은 아니다. [집계 수치](AUDIT.json)

## 정상 모델도 높은 ASR을 보이는 이유

**가설 한 줄: FUBA의 학습된 생성기는 독성 학습을 하지 않은 정상 모델에도 목표 오분류를 전이시킨다.**

공개 코드의 생성기는 고정한 분류기에 대해 다음 목표로 학습된다.

\[
G^* \approx \arg\min_G\;\mathbb E_x\,\mathrm{CE}\!\left(f_{\theta}\!\left(\operatorname{clip}(x+\operatorname{clip}(G(x),-.04,.04),-1,1)\right),8\right).
\]

따라서 ASR은 분류기의 속성 하나가 아니라 **분류기·공격 입력 생성기·시험 분포의 조합**이다.

\[
A(\theta,G,D)=\Pr_{(x,y)\sim D}\left[f_\theta(T_G(x))=8\mid y\ne8\right].
\]

이 생성기는 입력마다 달라지는 목표 지향적 적대 교란을 만든다. 백도어 학습이 없어도 전이 공격이 통하면 ASR이 높아질 수 있다는 설명을 정상 대조로 직접 확인했다. 특정 평가 표본을 새로 최적화한 것은 아니며 기존 생성기를 고정했다.

| 동일한 320장 중 비목표 288장 | 공격 학습 모델 | 정상 학습 모델 |
|---|---:|---:|
| 변형 없는 입력의 목표 오분류율 | 1.04% | 3.13% |
| 무작위 균등 잡음, 최대 크기 0.04 | 2.08% | 4.51% |
| 무작위 초기화 생성기 | 1.04% | 2.78% |
| 학습된 생성기, eval 모드 | 97.92% | 93.06% |
| 학습된 생성기, train 모드 | 96.18% | 92.01% |

**결과: 검사한 정상 모델에서 전이가 확인됐다.** 현재 ASR로 “백도어를 심었기 때문에 성공했다”와 “원래 정상 모델에도 통하는 적대 입력이다”를 구별할 수 없다. 생성기를 사용하는 것 자체는 FUBA의 의도된 공격 방식이다. 잘못된 부분은 이 정상 대조 결과를 확보한 뒤에도 ASR을 잠복 백도어의 활성화 증거처럼 사용한 해석이다.

**가설 한 줄: 원 코드가 음수 픽셀을 허용하는 것이 높은 정상 모델 ASR의 주원인이다.**

- 조건: 같은 생성기와 320장, 최종 입력 범위만 `[-1,1]`과 `[0,1]`로 비교.
- 결과: 최대 교란 크기 0.04에서 두 범위 모두 공격 모델 97.92%, 정상 모델 93.06%. 이 범위 차이로 현상을 설명할 수 없다.
- 생성된 교란을 1/4, 1/2로 줄이면 두 모델 모두 공격 반응이 줄었다. 정상 모델은 각각 20.49%, 54.51%다. 이는 원인 진단용 민감도 검사이며, ASR이 낮아지도록 공격 강도를 바꾼 값을 논문 재현 결과로 채택하지 않는다. [추가 집계](CLIP_AUDIT.json)

## FUBA 공개 코드에서 확인한 재현 문제 후보

**가설 한 줄: 공개 코드의 학습·강도 선택 구현은 논문의 위장 의도를 그대로 보장한다.**

| 실제 실행 소스에서 확인한 항목 | 확인 내용 | 원인 판단의 범위 |
|---|---|---|
| 위장 모델 일관성 손실 | `lossf = backdoored_loss + 0 * l2_loss` | 항의 기울기 기여가 0인 것은 확정. 논문과 저장소 설명이 내세우는 일관성 기제가 이 분기에서는 작동하지 않음 |
| 공격 강도 후보와 제출 값 | 후보는 γ=0.1…1.0, 선택한 0기반 인덱스에 다시 0.1을 곱해 제출 | 실제 제출은 선택 후보보다 0.1 작음. 첫 후보 선택 시 0, 통과 후보가 없으면 -0.1이 되는 경로가 존재 |
| 강도 선택 목적 | 임계값 이하인 후보 중 최대 ASR의 인덱스를 반환 | γ가 가장 큰 후보를 고르는 것과 일반적으로 다름. ASR이 단조롭다는 보장이 필요 |
| 로컬 학습 길이 | `local_epochs = 1`, `TRAIN_EPOCH = 20`을 함수 안에서 고정 | 설정의 `train_epoch`를 변경해도 이 루프 길이는 바뀌지 않음. 정상 학습 루프는 가용 전체 배치 수와 22배치 중 작은 수에서 끝남 |
| 위장 최종 제출 | 2단계 학습이 끝난 `net.state_dict()`를 그대로 제출 | 논문 Algorithm 2의 벡터 구성과 세부 대조가 필요한 지점. 현재 코드의 실제 동작과 논문식이라고 추정한 동작을 혼동하지 않음 |

강도 인덱스 문제는 원 함수에 합성 점수를 넣어 확인했다. 예를 들어 첫 후보 ASR만 임계값 이하일 때 평가한 강도는 0.1인데 제출식은 0을 만든다. 이는 **코드 경로의 반례**이며 해당 실제 라운드가 이 분기를 탔다고 확인한 실행 추적은 아니다. `attack()`은 백분율을 반환하므로 임계값 `10` 자체는 10%에 해당한다. 이 부분은 단위 100배 오류가 아니다.

**결과: 공개 코드 실행만으로 논문 기제가 보존됐다고 볼 수 없다.** 이 문제들은 실제 실행에서 수정하지 않고 남겨 둔 것으로 설정 기록에 명시돼 있었다. 원 소스를 보존한 것은 출처 추적에는 유용하지만 재현 성공의 근거가 되지 않는다. 각 항이 ASR에 미친 기여도는 같은 초기값·분할을 고정한 학습 대조로 분리해야 한다. 현재 감사에서 그 재학습 대조를 완료했다고 주장하지 않는다. [실제 소스 검사와 합성 사례](SOURCE_AUDIT.json), [저자 저장소](https://github.com/stcebra/FUBA)

FUBA 논문과 저장소는 학습 중 주입과 억제의 균형, 일관성 손실, 삭제에 의한 활성화를 핵심으로 설명한다. 현재처럼 삭제 전부터 98%인 결과는 이 의도와 맞지 않는다. 이번 웹 접근에서 IEEE 본문 전체는 로봇 검증으로 열리지 않아 기존 독해 기록의 λ=2 등 세부 수치는 새로 확인한 확정 사실로 사용하지 않았다. [논문 초록과 출판 정보](https://ieeexplore.ieee.org/document/11231135/)

## 삭제 전후 ASR이 서로 달라 보인 또 다른 이유

**가설 한 줄: 삭제 전후 ASR 차이는 평가 생성기를 고정하지 않아도 모델 변화만 나타낸다.**

\[
\underbrace{A(\theta_+,G_+,D)-A(\theta_-,G_-,D)}_{\text{모델과 생성기가 함께 변함}}
=\underbrace{A(\theta_+,G_-,D)-A(\theta_-,G_-,D)}_{\text{고정 공격 입력에서 모델 변화}}
+\underbrace{A(\theta_+,G_+,D)-A(\theta_+,G_-,D)}_{\text{생성기 변화 효과}}.
\]

이 등식은 같은 시험 분포와 생성기 실행 상태를 고정할 때 정확하다. 원 실행의 FUBA 로그는 각 학습 끝의 생성기를 쓰지만 최근 전후 실험은 삭제 전 생성기를 고정했다. 원 로그의 ASR 약 98.19% → 98.87%와, 최근 320장 고정 생성기 평가의 97.92% → 81.60%는 같은 질문에 대한 동일 조건의 숫자가 아니다. 두 경우 모두 삭제 전이 이미 높다는 재현 문제는 남는다.

**결과: 가설 기각.** 이후 결과에는 생성기 출처·시점·train/eval 모드·시험 표본 수를 ASR과 함께 붙인다. 고정 생성기 비교와 각 시점 생성기로 다시 공격하는 비교를 모두 할 수 있지만 한 종류로 합치지 않는다.

## 이전 탐지 결과를 어떻게 다룰 것인가

- BadFU 논문식 쌍과 큰 정상 탈퇴에서 Conv 점수가 겹쳤다는 관측은 유지한다. 실제 공격 활성화가 확인된 조건에서 해당 점수가 충분하지 않았다는 결과다.
- FUBA 기존 쌍의 응답 점수는 보존 모델에 대한 기술적 관측으로 남긴다. **정상 정확도가 유지됐다는 사실만으로 잠복 공격 재현에 유효한 쌍이라고 부르지 않는다.** 이 쌍으로 FUBA 잠복 공격 탐지의 성공·실패를 확정하지 않는다.
- 정확도가 붕괴한 FUBA 단축 FU는 탐지 성능에서 계속 제외한다. 원 FUBA의 100라운드 재학습은 정상 기능을 유지했으므로 두 절차를 같은 것으로 부르지 않는다. 단축은 5시점, SGD 0.01, 고정 생성기로 구성한 별도 변형이며 원 MPI의 Adam·공격 협력·생성기 재학습을 재현하지 않았다.

다음 재현 기준은 정상 기능 유지, 삭제 전 억제, 삭제 후 활성화, 같은 생성기의 정상 모델 전이 대조를 함께 보는 것이다. 원문식 복원 후보와 공개 코드 보존 실행은 별도 폴더에서 대조해야 한다. 높은 ASR만으로 통과시키거나, 결과를 맞추려고 사후에 교란 강도를 낮추지 않는다.
