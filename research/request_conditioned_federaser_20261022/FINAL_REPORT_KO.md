# 언러닝 전후 조건부 전환과 참여자 이력: 저장 모델 실행 보고서

2026년 10월 22일 · 실제 실행 완료 · 탐지에 clean 이미지·정답 트리거·역할 정보 미사용

## 1. 결론

**이번에 구현한 자료 없는 탐지기는 공격을 검출하지 못했다.** 전후 변화량 대신 원본 예측 보존과 조건부 목표 전환을 함께 요구하고, 동일 기능에 대한 요청자의 억제·잔류 참여자의 강화 이력을 확인했지만, 독립 입력에서 재현되는 조건을 확보하지 못했다. 위장자·주입자를 확정할 근거도 얻지 못했다.

**실제 트리거를 제공한 진단에서는 대표 BadFU c01의 합성 확인 입력 36장 중 30장에 전환이 나타났지만, 자동 조건 탐색으로는 이 전환을 찾지 못했다.** 따라서 이 사례의 직접적인 병목은 미지 조건의 탐색이다. 반면 저자 FedEraser f01에서는 실제 이미지에 강한 공격이 있어도 같은 합성 입력의 실제 트리거 반응이 약해 입력 생성의 한계도 확인했다. 정상 non-IID와 공격의 구별 불가능성을 보인 결과가 아니다. 오탐이 없더라도 공격 경보도 없는 기준을 유용한 탐지기로 채택하지 않는다.

비교는 첫 실행 11쌍, 과신 완화 및 정상 전체 삭제 대조를 추가한 실행 13쌍이다. 공통 11쌍을 두 번 검사했고 출발 모델을 공유하므로 24개의 독립 학습 실험이 아니다.

## 2. 실제로 사용한 정보

탐지 경로는 분류기 전후 상태, 구조·전처리, 신원에 연결된 보존 제출 모델/업데이트와 당시 글로벌 모델, 확인된 삭제 요청자 ID만 사용했다. 보존된 로컬 상태와 글로벌 상태가 있는 시점에서는 선형 근사 대신 실제 함수 차이를 계산했다. **그레디언트만 있고 대응 글로벌 상태나 BN 상태가 없을 때 같은 계산을 그대로 수행할 수 있다는 주장은 하지 않는다.**

모델에서 생성한 합성 입력은 pseudo-label 입력이다. 실제 클래스 의미나 정상 분포를 보증하지 않는다. 자연 이미지 320장과 실제 트리거는 탐지 점수·후보·참여자 선택이 고정된 뒤 평가에만 사용했다. 정상 FU 대조를 만드는 작업은 평가자의 비공개 학습 자료를 사용했으며, 그 자료를 탐지기에 넘기지 않았다.

## 3. 가설과 판정 관계

가설은 ‘큰 변화’보다 **동일 조건에서만 나타나는 전후 전환의 재현성**을 검사하면 정상 삭제와 구별할 정보를 얻는다는 것이다.

| 입력 | 언러닝 전 | 언러닝 후 |
|---|---|---|
| 원본 x | source s | 같은 s |
| 같은 조건 T를 적용한 x | s 유지 | 공통 목표 t≠s |

모든 목표 10개를 검색했다. 조건은 위치를 고정하지 않은 연속 마스크(총 질량≤32)와 공통 가산 변화(L∞≤16/255)다. 각 비교에서 클래스당 탐색 4장·독립 확인 4장, 총 80장의 합성 입력을 생성했다. 두 검색 목적함수와 두 조건군으로 40개 후보를 만들었다. 조건군과 최적화 예산은 한정되어 있으며, 입력 의존 생성기나 모든 트리거를 포괄하지 않는다.

원래 합성은 두 끝점의 분류 CE, BN 통계 사전항, TV를 사용했다. 과신 완화 대조는 label smoothing 0.2를 추가했다. 원래 합성 c01의 합성 source 확률 중앙값은 1.0000; 과신 완화 c01의 합성 source 확률 중앙값은 0.8207이었다. **두 번째 실행은 첫 실행 결과 일부를 본 뒤 정한 탐색적 수정**이며 독립 사전 등록 재현이 아니다. 임계값과 조건 예산은 바꾸지 않았다.

전환 후보는 탐색 입력의 source별 공동 전환율 하위 사분위수를 기준으로 고정했다. 동률이면 상대 비용이 작은 조건을 택했다. 확인에서는 원본 전후 일치≥90%, 목표를 제외한 9개 source 중 5개 이상에서 공동 전환≥80%를 요구했다. 이 수치는 충분한 정상 FU 집합으로 보정된 유의수준이 아니다. 하위 사분위수 선택은 최종 5개 클래스 규칙보다 강할 수 있으므로, 선택된 후보 외에 후보 전체의 최댓값도 진단으로 보고했다.

비교 기준선은 후보 40개 전체 중 탐색 입력의 최대 확률 차분을 선택했다. 따라서 목적함수 하나만을 격리한 기준선으로 해석하지 않는다. 이력 확장은 paired-CE 후보 20개에서 전환과 이력의 일치도를 함께 사용했다.

## 4. 체크포인트 종류와 1단계 결과

| 실행 | 후 모델 종류 | 백도어 학습 포함 사례의 경보/비교 | 깨끗한 사례의 경보/비교 | 악성 삭제 요청의 경보/비교 |
|---|---|---:|---:|---:|
| 원래 합성 | 유지 자료 재학습 | 0/4 | 0/5 | 0/3 |
| 원래 합성 | 저자 FedEraser | 0/2 | 0/0 | 0/1 |
| 과신 완화 대조 | 유지 자료 재학습 | 0/4 | 0/5 | 0/3 |
| 과신 완화 대조 | 저자 FedEraser | 0/2 | 0/0 | 0/1 |
| 과신 완화 대조 | 추가 정상 FU | 0/0 | 0/2 | 0/0 |

0/0은 해당 종류가 없다는 뜻이다. 백도어 학습 여부와 요청의 악성 의도는 서로 다른 정답이다. c02·f02는 감염된 모델의 정상 요청이다. 이미 공격이 활성화된 FUBA 등은 전후 신규 활성화가 없어도 감염 모델이며, 이 전환 검사에 걸리지 않았다는 이유로 안전하다고 판정하지 않는다. 표는 정답별 기술 통계이며 보편적 탐지율이나 0% 오탐률 추정이 아니다.

- c01–c09: 유지 자료 재학습 기준 모델. 실제 FedEraser 결과로 합산하지 않았다.
- f01: 저자 구현의 full6→remove5, 요청자 5. f02: cover5→remove1, 요청자 1. 둘 모두 학습에 백도어가 포함되어 깨끗한 음성 대조가 없다.
- n01·n02: 이번에 만든 정상 전체 참여자 삭제 대조. 아래처럼 보존 5개 시점을 이용한 변형 FedEraser이므로 저자 구현의 f01·f02와 같은 절차·학습 예산으로 취급하지 않는다.

최대 확률 차분 선택, paired 선택, 확인 가능한 이력을 결합한 경보에서 모두 분리의 증거를 얻지 못했다. 이력이 확인 불가능한 비교는 역할 성능 분모에서 제외했다.

## 6. 실제 트리거를 준 평가: 공격 부재와 관측 실패를 구분

원래 BadNet 기록의 트리거 자원을 보존된 공격 평가 이미지 5장의 픽셀과 대조했다. Paper32의 학습·평가 소스도 같은 badnet_original 기록을 사용함을 확인했다. 이를 c01·c02·f01·f02에만 실제 트리거 근거로 연결했다. 다른 FUBA 트리거가 같다고 가정하지 않았다. 평가 전후 탐지 파일의 해시도 동일했다.

| 합성 방식 | 비교 | 실제 이미지의 트리거 목표 예측 전→후 | 실제 이미지 네 칸 공동 전환 | 독립 합성 입력의 실제 트리거 목표 예측 전→후 | 합성 네 칸 공동 전환 |
|---|---|---|---|---|---|
| 원래 합성 | c01 | 55/288 (19.10%) → 288/288 (100.00%) | 201/288 (69.79%) | 0.00% → 83.33% | 30/36 |
| 원래 합성 | c02 | 55/288 (19.10%) → 51/288 (17.71%) | 13/288 (4.51%) | 0.00% → 0.00% | 0/36 |
| 원래 합성 | f01 | 232/288 (80.56%) → 287/288 (99.65%) | 47/288 (16.32%) | 0.00% → 2.78% | 1/36 |
| 원래 합성 | f02 | 52/288 (18.06%) → 42/288 (14.58%) | 9/288 (3.12%) | 0.00% → 0.00% | 0/36 |
| 과신 완화 | c01 | 55/288 (19.10%) → 288/288 (100.00%) | 201/288 (69.79%) | 33.33% → 94.44% | 22/36 |
| 과신 완화 | c02 | 55/288 (19.10%) → 51/288 (17.71%) | 13/288 (4.51%) | 30.56% → 25.00% | 1/36 |
| 과신 완화 | f01 | 232/288 (80.56%) → 287/288 (99.65%) | 47/288 (16.32%) | 0.00% → 2.78% | 1/36 |
| 과신 완화 | f02 | 52/288 (18.06%) → 42/288 (14.58%) | 9/288 (3.12%) | 2.78% → 2.78% | 0/36 |

실제 이미지 분모는 목표 클래스 0을 제외한 288장, 합성 입력은 36장이다. ‘네 칸 공동 전환’은 원본을 두 모델이 모두 원래 클래스로 맞히고, 조건부 입력은 전에는 원래 클래스·후에는 목표로 바뀐 개수다. 실제 이미지의 ASR과 합성 pseudo-label 입력의 목표 예측률은 구분해야 한다. 이 표는 **트리거를 제공한 원인 진단**이고 미지 트리거 탐지 성능이 아니다. 전체 공통 정답 입력을 분모로 한 값과 source별 값도 원자료에 보존했다.

**c01에서는 clean 입력 없이 만든 합성 입력에도 구분 신호가 남아 있었다.** 원래 합성의 독립 확인 입력에서 실제 트리거의 전환은 30/36(83.33%)이고, 감염 모델의 정상 요청 c02는 0/36이었다. c01에서 9개 source 중 6개는 4/4 전환을 보였다. 그럼에도 자동 탐색한 paired 후보 20개는 확인 입력의 공동 전환율이 모두 0이었다. 따라서 이 비교는 ‘어떤 조건을 주어도 차이가 없다’는 경우가 아니라 **유효한 조건은 존재하지만 현재 검색이 찾지 못한 경우**다. 이는 평가자가 트리거를 제공한 뒤 확인한 제한된 존재 증거이며, 미지 조건 탐지가 해결됐다는 뜻은 아니다.

과신 완화는 c01의 실제 트리거 목표 예측률을 높였지만, 언러닝 전에도 목표로 넘어가는 입력이 늘어 공동 전환은 30/36에서 22/36으로 줄었다. 자신감을 낮추는 것과 전후 판정 관계를 잘 보존하는 것은 같지 않았다.

f01은 실제 이미지의 ASR이 80.56%→99.65%로 이미 전부터 활성화된 공격이다. 따라서 새 전환만으로 감염 전체를 검사하기 어렵고, 실제 트리거를 준 합성 입력에서도 공동 전환이 1/36에 그쳤다. **c01의 조건 탐색 실패와 f01의 입력 관측 한계를 같은 원인으로 합치지 않는다.**

## 7. 정확도가 무너지지 않는 정상과 Conv·FC 변화 비교

상대 변화는 해당 층의 `L2(후−전)/L2(전)`이다. 구조가 같은 모델끼리의 기술 통계이며 공격 기준으로 쓰지 않았다.

| 비교 | Conv 상대 변화 | FC 상대 변화 | 실제 이미지 clean 정확도 전→후 |
|---|---:|---:|---:|
| c01 위장 자료 삭제 | 8.13% | 16.83% | 90.00% → 88.75% |
| c03 정상 클래스 집중 삭제 | 7.58% | 16.79% | 88.75% → 89.06% |
| c09 정상 같은 장수 임의 삭제 | 7.40% | 14.25% | 88.75% → 89.38% |
| n01 정상 참여자 전체 삭제 | 10.05% | 53.34% | 88.75% → 80.62% |

정상 c03에서는 정확도가 유지되면서 FC 변화가 공격 c01과 거의 같았다. 따라서 ‘정상 모델을 심하게 망가뜨렸기 때문에 변화량이 겹쳤다’는 경우에만 해당하는 혼동은 아니다. 그렇다고 두 모델의 모든 조건부 함수가 같다는 뜻도 아니다. **같은 파라미터 변화 크기 안에서도 어떤 입력 조건에 반응이 집중되는지는 다른 문제**다.

| n02 | 4 | 9,668/50,000 (19.336%) | 88.75% → 81.25% | 0 |

정상 원본 CIFAR 이미지·라벨로 독성/위장 위치를 복원한 5인 분할은 [11,395, 9,647, 9,641, 9,649, 9,668]장이었다. 기록의 집계 비중과 일치하는지 확인했다. 이 두 대조는 일부 샘플 삭제가 아닌 전체 참여자 삭제다.

각각 5개 보존 시점에서 잔류 참여자를 1 epoch씩 재보정하고, 이전 파라미터 업데이트의 노름과 새 방향으로 갱신했다. BN 버퍼는 재보정 결과를 사용했다. 전체 원 학습을 반복한 재학습이나 저자 FedEraser의 전체 보존 일정과 같지 않으며, 정확한 망각을 인증한 결과도 아니다. 정확도 손실은 위 표 그대로 보고한다. 이 단축 절차의 정상 대조에서 경보가 없었다는 사실만으로 저자 FedEraser 공격과의 분리나 non-IID 강건성이 입증되지는 않는다.

## 9. 2단계: 동일 기능의 억제·강화 이력

이력 함수는 `A = [z_t(Tx)−z_s(Tx)]−[z_t(x)−z_s(x)]`다. 한 클래스의 입력 독립 bias는 이 차분에서 상쇄된다. 각 제출 모델의 A에서 그 라운드 글로벌 모델의 A를 빼는 **유한 함수 차이**를 계산했다. 순수 Conv 그레디언트의 인과 영향이나 라운드별로 더할 수 있는 기여라고 부르지 않는다.

원본 입력의 중심화 로짓 변화 RMS+0.1로 정규화한 값, 원값, 집계 가중값을 모두 보존했다. 정규화가 non-IID·샘플 수 효과를 모두 제거한다는 가정은 하지 않았다. 시점 1/3/5를 탐색, 2/4를 확인에 사용했고, 선택한 동일 잔류 참여자의 강화와 요청자의 억제가 확인 시점에도 지속되는지 검사했다.

요청자 ID가 로컬 원자료에서 확정되지 않은 c02·c07·c08은 이력 검사에서 제외했다. FUBA c05·c06은 요청자 4가 보존 5시점에 한 번도 없어 요청자 억제를 확인할 수 없다. f01·f02는 마지막 한 시점만 있어 독립 이력 확인이 불가능하다. 이들은 무혐의도 탐지 실패의 역할 정답도 아니다.

c01은 P와 C가 같은 참여자 0 안에 있는 구성이다. 남은 다른 ID 중에서 주입자를 반드시 찾아야 한다고 요구할 수 없다. 이 경우 합쳐진 제출 기록의 순효과가 상쇄될 수 있으며, 잔류 강화 후보를 실제 주입자로 지목하지 않는다. 표의 후보 번호는 중간 계산값이고 공격자 판정이 아니다.

과신 완화 c01에서 이력 부호 확인만 True였던 후보의 목표는 4였고, 선택된 잔류 강화자는 정상 참여자 1이었다. 실제 공격 목표는 0이다. 행동 조건을 통과하지 못해 최종 경보는 False였다. **요청자의 억제와 다른 참여자의 강화가 독립 시점에서 확인되어도, 그 기능이 실제 공격이라는 별도 근거 없이 역할을 확정할 수 없었다.**

## 10. 이전 패치 결과와 이번 결과가 다른 이유

기존의 [패치·Conv·FC 분석](../STAGE1_BADFU_TEST_20261021/protocol.json)은 라벨 있는 실제 clean 참조 입력을 사용했다. 이번 실행은 그 정보를 제거하고 모델만으로 만든 입력에서 조건을 찾았다. 앞선 원인 진단은 실제 트리거까지 제공했다. 서로 다른 관측 조건의 결과다.

이번 검사가 실패했다고 이전 저장 모델의 공격이 사라졌다는 뜻은 아니다. 모델 출처, 전처리, 실제 트리거 반응을 따로 확인했다. 또한 실제 FU와 재학습을 분리했고, 초기 저자 모델 로딩에서 `model.` 키 접두사가 맞지 않았던 오류를 고친 뒤 점수를 완성했다. 그 수정은 모델 로딩 수리이며 탐지 규칙 변경이 아니다.

특히 FUBA의 입력 의존 공격 생성기와 이번 공통 가산 조건은 같은 함수군이 아니다. 보존된 이 FUBA를 다른 FedUBA 논문·구현까지 대표하는 것으로 확대하지 않는다. 이전 분석에서 발견된 BN·비선형 영향 문제 때문에 이번에는 Taylor 방향 점수 대신 제출 모델의 실제 함수 차이를 썼지만, 이 변경만으로 입력 일반화가 해결되지는 않았다.

## 11. 연구 가설 판정과 신규성의 위치

가설 1 ‘전후 조건부 전환의 자료 없는 탐색이 최대 확률 차분보다 유용한 구분을 제공한다’는 **이번 구현·예산에서는 지지되지 않았다.** 가설 2 ‘동일 기능의 억제·강화 이력이 역할 정보를 추가한다’도 검증하지 못했다. 충분한 조건부 기능과 독립 역할 이력이 함께 확보되지 않았다.

선행 비교는 [기존 문헌 보고서](../limited_information_literature_20261022/REPORT_KO.md)에 있다. FilterFL과 겹치는 전후 모델의 기능 탐색 자체나, FLForensics와 겹치는 의심 기능의 이력 추적 자체를 신규성으로 주장하지 않는다. 검증할 연구 차이는 **삭제되는 억제 기여와 남는 악성 기능의 연결을, 정상 전문 참여자의 지식 삭제와 구별하는 판정 관계**다.

이번 결과에서 다음 검증의 우선순위는 분명하다. c01처럼 합성 입력에 신호가 존재하는 경우에는 **미지 조건 검색의 최적화와 여러 입력에서의 재현성**부터 개선하고, f01처럼 실제 조건에도 합성 반응이 약한 경우에는 입력 생성·중간 표현 검사를 먼저 바꿔야 한다. 이력 부호만의 일치는 오지목 가능성이 있어 독립 판정 근거로 채택하지 않는다. 이력을 조건 생성에 직접 결합하는 방식도 다음 가설일 수 있지만 아직 실행·성능 검증하지 않았다. 정상 클래스·도메인 전문 참여자에서의 반증이 필요하며, 현재 결과로 논문 신규성이나 해결된 탐지법을 선언하지 않는다.
