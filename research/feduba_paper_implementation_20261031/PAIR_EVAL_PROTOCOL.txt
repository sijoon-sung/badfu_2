가설: 고정된 FedUBA δ와 평가 규칙을 실제 pre/동일 원ID 정상FU/공격FU 세 모델에 똑같이 적용하면 잠복 활성화의 최소 필요조건을 정상 FU의 변화와 구분해 판정할 수 있다. 관련 R03/R02/N02/D08/D15. 새 관측은 실제 세 모델 각각10000장 클린/triggered logits와 정확 원ID·라벨·비target 분모, 독립 코드의 전체 재추론과 정수 수 일치다. SSS/보정norm을 새 탐지기로 사용하지 않는다. 이는 공격 입력 적격성 평가이며 D08 공격0.75848 대 큰 정상0.75525/0.76188, D15 공격7/정상8 반례를 해결하거나 trigger 계열 독립 탐지를 검증하지 않는다.

계산 전 코드/수치 계약: PAIR_EVAL_PROFILE은 launchfalse이며 실제 SSS/FU/평가를 시작하지 않는다. evaluate_pair/verify_pair_evaluation/paired_controller와 source-only freeze를 PR에 먼저 게시한다. 현재 STG100/5/100의 source/profile/freeze나 진행 중 모델은 수정하지 않는다. 실제 활성화는 전체 STG/audit 완료 뒤 현재 정상 case의 guard/select_case/hash/payload, 고정 SSS/FU/평가 launchprofile·freeze를 연결하는 별도 명시 실행계약에서만 한다. 실 평가에는 실제 정상FU와 공격FU의 각각20R·독립CPU audit 완료가 필요하다. 성능을 보고 branch를 생략하지 않는다.

평가: target2, 최종 STG δ를 SSS/두 FU와 같은 SHA로 고정하고 배수1.5·clip(x+1.5δ,-1,1), 원label·공식 test10000 순서·B128(79batch)·contiguous NCHW FP32다. 원label2의1000장은 ASR 분모에서 제외하며 실제 labels로9000을 확인한다. 클린 CA는10000 모두 쓴다. trigger 입력도 전체10000을 재추론하되 target 원label의 성공을 ASR 분자에 넣지 않는다. pre-ASR, 정상FU ASR-B, 공격FU ASR을 별도 기록한다. primary와 독립 검산 각각60000 sample-forward/474 모델forward다. 같은 test 파일 SHA를 준비 영수증과 대조한다.

독립 범위: primary는 torchvision ToTensor/Normalize.5 및 DataLoader로 정규화 입력79파일을 저장하고 세 모델의 각79개 logit 파일을 보존한다. 독립 코드는 primary helper/counts를 import하지 않고 원uint8에서 NCHW float/div255/sub.5/div.5와 직접 clip을 전10000장 재구성한다. 저장 입력과 torch.equal, 모든 sourceID/label, 실제 checkpoint/δ SHA·payload, 고정 theta/BN을 검사한다. 동일 DISLAB GPU에서 세 모델 전체를 새 프로세스로 재추론하고 호출 순서를 trigger→clean으로 바꾸며 Python max/sum으로 모든 예측·정수 수를 다시 센다. 모든 argmax와 counts는 정확히 같아야 한다. logits 허용치는 계산 전 atol1e-6/rtol1e-5로 고정하고 최대 오차를 남긴다. 동일 장치 재추론이지 독립 아키텍처 구현이나 CPU/GPU 동등성 증명이 아니다.

수치 장치: AMP/TF32는 끄고 matmul highest, cudnn benchmarkfalse/deterministictrue, torch deterministic algorithms true, CUBLAS_WORKSPACE_CONFIG=:4096:8, CPU1thread를 두 평가에 동일 적용한다. 이는 미실행 평가의 사전 선언이며 기존 FL/STG/FU 학습 수치 설정을 소급 변경하지 않는다. kernel/precision/runtime 오류 또는 예측 불일치를 발견하면 보존하고 원단계를 진단하며 사후 tolerance/장치/배치/분모/trigger를 바꾸지 않는다. source·모델 파일/실제 theta·BN·δ는 평가 전후 불변이어야 한다.

사전 최소 gate: 기존 FU_PROFILE의 preASR<=20/attack>=80/증가>=50pp/benignFU초과>=50pp/세CA>=80/후CA하락<=5pp를 변경하지 않는다. 후CA 하락은 benign과attack 각각에 적용한다. primary는 유리수로 경계 비교하고 독립 검산은 실제10000/9000의 정수 수에서 별도로 비교한다. 논문의 정확 평균·서버 탐지 threshold·unknown-trigger 성공을 의미하지 않는다. 조건 미달도 모든 원모델·성능·대조·실패를 남기고 전달한다. 좋은 시드/epoch/δ/분모 선택이나 중간 gate 조기 중단은 없다.

새 유한 CPU 계약: 실모델/실자료를 읽지 않는23개 합성 NCHW 입력·B7/tail2에서 plus1.5와 양쪽 clip/0채널 불변을 binary-exact scalar로 확인한다. labels의 target4개를 분모에서 제외하고 알려진 logits·동점argmax·역순ID·직렬화 뒤 정수 수를 검사한다. 실제 FU gate 수치의 경계 통과와 단 하나의 count 변경 실패를 확인한다. 기존 core/SSS/FU engine/원AST 유한 검사를 반복하지 않는다. PAIR_EVAL_CPU_FREEZE를 PR 선게시한 뒤 DISLAB CPU에서 배타 ONCE로 한 번만 수행한다. 이 fixture의 통과는 실제 평가/공격성공이 아니다.

paired_controller는 code-only이며 아직 launchprofile이 없다. 향후 새 일회 부모만 SSS→CPU audit→benignFU→CPU audit→attackFU→CPU audit→primary evaluation→독립 전체 evaluation을 순차 수행한다. 각 GPU 단계 전 원 작업 실제 종료/24h 이내 고정 resourceguard를 기다리며 다른 앱 종료·guard 우회·완료 유한 작업 재실행은 없다. 모든 child 실제 PID와 state/log를 남긴다. 실패는 자동 retry 없이 원prefix·source/hash·trace를 보존한다. 완료 뒤에도 모델/실제 기여/optimizer/RNG/전체로그의 양쪽 전달·봉인/catalogue/index guards 및 탐지 검증이 남으므로 전체 목표/heartbeat를 종료하지 않는다.
