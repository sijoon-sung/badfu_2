가설: 저자 공개 MNIST/IBA 여섯 생성기를 고정 eval 모드로 사용할 때, 각각의 공개 post 분류기에서는 ASR60% 이상이지만 독립 정상 MNIST 분류기에서는 ASR10% 미만이다.

관련 R02/R04/D08/D15 및 별도 FedUBA R03 식별 기록. INDEX, R02 공개DBA 보고서/정정, R04 원 보고서, D08/D15 원 실패를 읽었다. 새 관측은 지금까지 CPU 구조만 확인한 공개 IBA6쌍의 실제 전체 평가와 동일 변형을 정상 분류기에 적용한 전이율이다. 기존 DBA6평가, 실제 Retrain100, gamma/redraw/fullbatch/optimizer 진단은 재실행하지 않는다.

입력은 stcebra/FUBA@bc233610aca36e1647d0c815597cc7148292139d의 이미 Git blob 검증한 global/backdoor_{distillation,federaser,pgd,retrain,robustfu,sga}_iba_mnist 각6개다. 이전 PREPARED.json의 각 원본/정규 state 해시를 바인딩한다. 새 case fuba.author.bc233610.mnist.iba.post6.20261115 / diagnostic과 정상 case benign.fuba.mnist.iid.s20261023.round20.20261115 / diagnostic을 별도 catalogue에 등록하고 select_case.py와 외부 manifest/seal을 검증한 뒤 소비한다. 기본 case는 바꾸지 않는다.
정상 대조는 R04의 원 20R/2local-epoch 정상 before.pt 하나다. 원 결과/독립검사/프로필/benchmark.py 해시와 payload_key=null을 명시한다. 100R/50epoch 대응 정상 대조가 아니며 이 모델과의 차이를 공격의 인과 효과나 non-IID 탐지로 확대하지 않는다. 원 모델을 재학습하지 않는다.

공개 model.py의 생성기는 MNISTAutoencoder(288963 parameters)다. 보충자료 II.B의 모든 데이터셋 U-Net 문구와 다르다. 공개 평가함수 attack은 classifier.eval()만 호출하고 generator 모드를 지정하지 않는다. 다음 두 조건을 사전에 모두 고정한다.
1. 주 조건: 각 canonical generator의 고정 eval 모드. BN buffer와 모든 파라미터는 전후 불변이어야 한다.
2. 수치 진단: canonical generator를 새로 로드한 train 모드. 각 method/독립경로마다 다시 원 상태에서 시작한다. 157 batch의 BN buffer 변화는 복사본에만 남기고 저장한다. 이를 학습된 가중치 변경이나 새 FU로 세지 않는다. 유리한 모드를 보고 주 조건을 교체하지 않는다.

MNIST 공식 test10000/target8 제외9026, ToTensor[0,1], FP32 contiguousNCHW, batch64/순서고정/마지막16포함, deterministic/noTF32, noise=clamp(.3*G(x),-.05,.05), input=clamp(x+noise,-1,1)이다. 같은 생성 입력을 post/정상 두 모델에 넣는다. L-infinity .05는 연산 제약 감사이며 탐지 점수가 아니다. 공개 attack/test AST를 별도 새 모델/생성기로 실행해 모든 정수 CA/ASR와 train-mode 최종BN 상태를 대조한다. 라벨 변경이 원자료에 번지지 않아야 한다. 저장 예측으로만 후속 표/그림을 만든다.

주 가설은 eval 모드의 여섯 조건 모두 postASR>=60 및 정상ASR<10일 때만 지지한다. BA와 clean-target-bias는 전부 보고하고 SGA에 임의 BA97 기준을 논문 기준으로 부과하지 않는다. 높은 정상 전이가 하나라도 있으면 그 조건에서 ASR을 공격 학습 특이적 증거로 쓰지 않는다. 공개 pre/history/seed/FU 로그가 없으므로 어떤 결과도 새 실제 FU, 잠복 전후쌍,10seed 평균 또는 전체 논문 재현을 완성하지 않는다.
이 정상 IID 대조는 D08 공격.75848 대 정상.75525/.76188 및 D15 공격7/정상8의 큰 benign non-IID 삭제 반례를 해결하지 않는다. 트리거 종류 독립 탐지나 서버 방법을 제안하지 않는다.

source/hash/shape/nonfinite/원함수 정수 불일치 또는 입력 변경이면 해당 실행을 실패 보존하고 중단한다. 목표/epsilon/clip/배치/mode/기준을 결과에 맞추지 않는다. 기존 util<=5/free>=2500MiB/RAM3GiB/disk10GiB/경쟁훈련부재 guard를 적용한다. 원본 앱과 finite 작업은 종료/재시작하지 않는다. 한 번의 CPU 준비 뒤 한 번의 GPU 평가, 결과/실제 복사본/예측/로그 양쪽 전달과 해시검사를 한다. 새 FL/FU optimizer step은 0이다.
