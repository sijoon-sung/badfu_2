# 큰 정상 참여자 삭제와 공격을 구별하는 서버 관측 특징 검증

2026년 10월 22일 · 사용자 PC RTX 4060 Laptop · 보존 모델 22개와 실제 전후 비교 13쌍

**현재 채택할 수 있는 BadFU와 FUBA 공통 탐지 특징은 확보하지 못했다.** 중간 표현의 출력 쏠림, 정상 과제 망각 동역학, 서버가 직접 심은 진단 과제의 유지율을 검토·실행했다. 큰 정상 참여자의 삭제와 독성 학습에 공통으로 반응하는 경우가 남았다. 문헌의 성공 조건을 우리 조건의 성공으로 옮겨 쓰지 않는다.

모델 검사 44건, 공개 정상 과제 망각 진단 176건, 개별 제출 모델 진단 52건을 완료했다. 별도로 새 진단 과제를 삽입한 통제 학습 48건을 완료했다. 같은 모델과 자료를 공유하는 반복이므로 독립 FL 실험 320여 회로 해석하지 않는다.

## 1 특징의 원리와 서버가 필요한 정보

| 후보 특징 | 발상의 출처 | 서버가 필요한 정보 | 이번 결과 |
|---|---|---|---|

| 정상 과제를 잊힐 때의 누적 손실 | MASA의 정상 과제 망각과 모델 융합 | 공개 과제 자료. 원래의 참여자 필터링에는 개별 제출 모델도 필요 | 큰 정상 삭제의 반응이 공격보다 큼 |

[FreeEagle](https://www.usenix.org/system/files/usenixsecurity23-fu-chong.pdf)은 입력 대신 중간 표현을 최적화하고 출력 확률 행렬의 이상도를 검사한다. 논문의 검사 입력이 자료를 요구하지 않는 것과 새 환경의 임계값 보정이 필요 없는 것은 다르다. 이번에는 ResNet18의 두 절단 위치와 유한 최적화 예산을 명시해 원리를 이식했다.

[MASA](https://arxiv.org/html/2411.01040v1#S4)는 정상 proxy 과제의 망각 손실로 제출 모델을 필터링하며, non-IID의 망각 차이를 줄이기 위해 제출 모델들을 융합한다. 저자 공개 코드의 상승 학습·클리핑·융합·MDS를 참고했다. 글로벌 전후 모델에 같은 진단을 수행하는 부분은 우리 확장이다.

[BackdoorIndicator](https://arxiv.org/html/2405.20862v1#S3.SS3)는 서버가 OOD 과제를 심고 참여자가 그 모델에서 학습한 뒤 유지율을 검사한다. Table 4의 non-IID α=0.2, poisoned learning rate 0.01에서 TPR 98.0%, FPR 19.7%를 보고한다. 이는 원 논문 조건의 결과다. 큰 정상 참여자 FU와 BadFU·FUBA의 억제 기여 제거를 검증한 수치는 아니다. 논문은 동기가 된 백도어 간 유지 현상이 임의의 모든 조합에서 성립하는 것은 아니라고도 명시한다.

추가 FU 선행인 [Malicious Forgetting, INFOCOM 2026](https://wenwei-zhao.github.io/publication/conference-paper/3/)도 조율된 백도어 업데이트의 방향 부분공간 이탈을 탐지한다고 설명한다. 확인 범위는 저자 초록이며, 큰 정상 참여자 삭제 대조나 전체 수식을 확인한 기준선으로 사용하지 않는다.

## 2 중간 표현의 출력 쏠림 검증

**가설 한 줄: 트리거를 모르는 중간 표현의 출력 쏠림은 큰 정상 참여자 삭제보다 공격 모델에서 일관되게 크다.**

- 조건: 분류기 22개, 전후 비교 13쌍. layer2 뒤를 주 절단점, layer3 뒤를 민감도 절단점으로 고정했다.
- 최적화: 클래스마다 두 초기값, Adam 200회, 학습률 0.05, L2 norm 계수 0.005, ReLU 이후 표현을 음수가 되지 않게 제한했다.
- 측정: 클래스별 가상 표현 두 개의 평균을 분류기에 넣어 비대각 확률의 열 평균 v를 구했다. M=(max(v)−Q3)/(Q3−Q1), M′=abs(M−1). 전후 M′의 최댓값과 M의 절대 변화량을 별도 저장했다. 실제 목표·트리거·ASR은 선택에 쓰지 않았다.
- 결과: 대표 BadFU M′는 12.983이었지만 이전 정상 비교는 14.570이었다. 같은 방법에서 FUBA 공격 0.799, 정상 0.695의 한 쌍 차이만으로 탐지 성능을 확정하지 않는다. 모든 가상 표현은 최적화한 자기 클래스로 분류됐으나, 그 사실이 공격 특이성을 보증하지 않았다.
- 판정: 공통 탐지 특징으로 채택하지 않는다. 큰 정상 전체 삭제 두 건보다 높은 사례가 있어도 클래스 집중 삭제와 다른 정상 학습 대조를 통과해야 한다.

## 4 서버가 직접 심은 진단 과제 검증

**가설 한 줄: 서버가 심은 OOD 진단 과제의 유지율은 정상 자료량 증가보다 독성 목표 학습에 선택적으로 반응한다.**

서버는 균등 난수 이미지 200장에 임의의 균형 라벨을 배정하고, 복사한 정상 모델에 200 mini-batch로 과제를 심었다. 원래 과제의 BN 버퍼와 지표 과제의 BN 버퍼를 분리했다. 같은 초기 지표 모델에서 정상 균형 자료 2,048장, 정상 편중 자료 2,048장, 같은 편중의 8,192장, 독성 25% 혼합, 독성 25%와 위장 25% 혼합, 억제 자료 25% 학습을 각각 비교했다.

독성·위장 학습 자료는 평가자의 비공개 모의 참여자만 구성한다. 서버 점수 함수는 반환된 분류기와 서버 자신의 난수 입력·임의 라벨만 사용한다. 실제 트리거·공격 목표·ASR은 점수 저장 후 별도 평가 함수에서만 검사했다.

BadFU 쪽은 보존한 실제 위장 이미지, FUBA 쪽은 보존한 s42 입력 의존 생성기를 사용했다. FUBA 생성기·억제자의 전체 최적화와 학습 전체를 재현하지 않았다. 두 방식에 같은 정상 분할을 사용하고 독성 혼합 비율을 통제한 **한 번의 로컬 학습 원리 파일럿**이다. 큰 정상 참여자의 실제 삭제 실험으로 바꾸어 부르지 않는다.

정상 편중 8,192장 학습도 BadFU 방식에서는 두 challenge seed 모두 최대 지표 정답률 100%를 보였다. 독성 학습도 95%, 100%였으므로 단순 유지율로 구별되지 않았다. 더구나 지표 삽입 자체가 정상 정확도를 크게 훼손했다. 따라서 이 단축 설정은 유효한 배포 탐지기로 채택하지 않는다.

## 5 출력 쏠림을 뺀 지표 유지율 검증

**가설 한 줄: 정상 기능을 보존하고 출력 쏠림을 뺀 지표 유지율은 큰 정상 기여와 독성 학습을 구별한다.**

첫 파일럿의 정상 경보와 기능 손상을 확인한 뒤 정한 탐색적 후속 실험이다. 다른 challenge seed 두 개를 사용했지만 같은 사전 학습 모델이므로 새로운 FL 학습 seed 재현은 아니다. 공개 입력 500장에서 삽입 전 예측을 보존하는 distillation 항을 추가했다. 이 입력의 정답 라벨은 삽입 학습에 사용하지 않았다. 불안정한 첫 주입 실행은 점수를 만들기 전에 중단됐고, 전체 기울기 norm 상한 20을 명시해 다시 실행했다.

단순한 목표 클래스 출력 쏠림을 제거하려고 다음 값을 계산했다.

\[
J_c=P(\hat y=c\mid u=c)-P(\hat y=c\mid u
e c),\qquad S=\max_c J_c.
\]

u는 서버가 난수 지표에 배정한 라벨이다. 이는 TPR−FPR인 [Youden의 J 통계](https://acsjournals.onlinelibrary.wiley.com/doi/10.1002/1097-0142%281950%293%3A1%3C32%3A%3AAID-CNCR2820030106%3E3.0.CO%3B2-3)를 지표 유지율에 적용한 것이다. 새 통계 자체의 발명으로 주장하지 않는다. 경보 기준 0.5는 후속 실행 전에 고정했으나 충분한 정상 FU 집합으로 보정한 유의수준은 아니다.

**조건부 수학 검산:** 모든 지표 입력을 같은 클래스 c로 예측하면 두 확률은 모두 1이므로 J_c=0이며 다른 클래스의 J도 0이다. 단순 클래스별 정답률은 이 경우 100%가 될 수 있다. 이 항등식은 일정 출력의 혼동만 제거하며 모든 non-IID 변화를 제거하는 보장이 아니다.

실제 후속 BadFU 방식의 한 정상 편중 학습은 200장 모두를 클래스 1로, 독성 학습은 200장 모두를 클래스 0으로 보냈다. 양쪽 최대 정답률은 100%, J는 모두 0이었다. 이 두 원인을 단순 유지율 하나로 분리할 수 없음을 직접 확인했다. 다만 이 BadFU 주입에서는 모든 지표 클래스를 학습하는 데 실패해 탐지 성능 판정에서 제외했다.

지표 학습과 정상 정확도 보존 상태는 다음과 같다. 정상 정확도 허용 감소 5%p는 후속 실험 전에 고정했다.

| 실행 | 구조와 challenge seed | 지표 클래스별 최소 정답률 | 지표 삽입 전후 정상 정확도 | 유효성 |
|---|---|---:|---|---|
| 원리 파일럿 | BADFU 21 | 100.0% | 85.62% → 15.94% | 제외 |
| 원리 파일럿 | BADFU 22 | 100.0% | 85.62% → 22.19% | 제외 |
| 원리 파일럿 | FUBA 21 | 100.0% | 77.81% → 50.00% | 제외 |
| 원리 파일럿 | FUBA 22 | 100.0% | 77.81% → 45.94% | 제외 |
| 쏠림 보정 확장 | BADFU 23 | 0.0% | 85.62% → 55.31% | 제외 |
| 쏠림 보정 확장 | BADFU 24 | 0.0% | 85.62% → 53.75% | 제외 |
| 쏠림 보정 확장 | FUBA 23 | 100.0% | 77.81% → 72.81% | 통과 |
| 쏠림 보정 확장 | FUBA 24 | 100.0% | 77.81% → 75.31% | 통과 |

FUBA 방식의 후속 두 challenge에서는 두 유효성 조건을 통과했다. 그러나 J도 정상과 독성을 분리하지 못했다.

| 통제 학습 | 첫 challenge의 J | 둘째 challenge의 J |
|---|---:|---:|
| 정상 균형 2,048장 | 0.844 | 0.889 |
| 정상 편중 2,048장 | 0.444 | 0.789 |
| 정상 편중 8,192장 | 0.322 | 0.761 |
| 독성 혼합 학습 | 0.267 | 0.583 |
| 독성·위장 혼합 학습 | 0.344 | 0.500 |
| 억제 자료 학습 | 0.689 | 0.711 |

정상 균형 학습의 0.844·0.889가 독성 학습의 0.267·0.583보다 높았다. 출력 쏠림만 제거하는 수정으로 공격 특이성이 생기지는 않았다. 이 표는 한 라운드 원리 검증이며 실제 FU의 검출률이 아니다.

## 6 FUBA 입력 반응의 공격 특이성 확인

**가설 한 줄: 보존한 FUBA 생성기 입력의 높은 목표 예측률은 독성 학습 모델에 특이적이다.**

이 파일럿에 쓴 정상 FUBA s42 모델은 독성 학습을 추가하기 전부터 같은 s42 공격 생성기에 95.49%의 목표 예측률을 보였다. 평가 분모는 목표 8을 제외한 실제 이미지 288장이다. 따라서 이 생성기 입력에 대한 높은 ASR만으로 학습된 백도어의 존재나 독성 학습의 기여를 입증할 수 없다. 일반 적대적 전이와 학습된 백도어 효과를 대조해야 한다.

이는 이 파일럿의 s42 자원에 대한 결과다. 본실험 전후 c05의 s20 생성기를 정상 쌍에 교차 적용한 새 결과로 혼동하지 않는다. 실제 생성기는 서버 점수에 넣지 않았다. 현재 공격 검증에서 공격자 성공 지표와 서버가 구별해야 하는 학습 기여의 특이성을 분리해야 한다는 추가 근거다.

## 7 채택 여부와 다음 검증의 조건

| 확보한 근거 | 연구에서 사용할 수 있는 범위 |
|---|---|
| 실제 서버 정보로 계산하는 세 종류의 특징과 지표 혼동 행렬 | 재현 가능한 비교 기준선 및 실패 원인 분석 |
| 큰 정상 전체 삭제에서 망각 반응이 공격보다 큰 사례 | 큰 학습 기여와 공격을 같은 이상 점수로 읽는 문제의 반례 |
| 일정한 클래스 출력은 J에서 정확히 0이 되는 항등식과 실제 사례 | 단순 출력 쏠림 제거. 공격·정상 구별 보장으로 확대하지 않음 |
| 지표 학습·정상 기능 보존을 만족한 FUBA 방식에서도 점수 중첩 | 해당 능동 진단 확장도 그대로 채택하지 않음 |

**단계 1의 공통 탐지 주장은 보류한다.** 원래 공격이 실현된 조건에서, 같은 삭제량·클래스·도메인 기여를 가진 정상 전체 탈퇴를 넘는 기능 차이를 독립적으로 보여야 한다. 지금 얻은 점수에 맞춰 공격의 정의를 바꾸거나 임계값·특징을 사후 조합해 성공으로 보고하지 않는다.

다음 후보는 논문 이름만으로 늘리기보다 필요한 관측 정보를 먼저 고정한다. FLForensics처럼 실제 의심 오분류 입력을 추가 확보하는 경우와, BackdoorIndicator처럼 서버가 학습 절차에 진단 과제를 추가하는 경우는 서로 다른 문제다. 후자는 기존에 저장한 제출을 지표 삽입 모델에 더해서 소급 검증할 수 없다. 반드시 그 모델에서 새로 계산한 제출이 필요하다.
