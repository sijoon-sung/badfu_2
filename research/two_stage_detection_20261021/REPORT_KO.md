# BadFU와 FedUBA 계열의 두 단계 탐지 연구 보고서

작성 기준일 2026년 10월 21일

**해석 정정:** 아래 파일럿의 주 비교는 마지막 제출분 제외이며 실제 언러닝 전후 패치 검사의 재현이 아니다. 그 실패로 기존 패치가 작동하지 않는다고 결론 내릴 수 없다. 기존 실제 전후 신호와 Conv FC 결과를 [비교 조건 재점검](PATCH_COMPARISON_AUDIT.md)에 연결했다. clean 기준 자료와 신규성 제약은 유지된다.

## 핵심 결론

연구의 중심은 **현재 백도어가 드러나는지**와 **특정 삭제가 잠복한 백도어를 활성화하는지**를 구분하고, 그 다음에 강화 역할과 억제 역할을 식별하는 것이다. 정상 non-IID에서도 반대 방향의 업데이트와 큰 모델 변화가 생긴다. 따라서 상쇄 자체나 큰 점수 하나로 악의를 확정할 수 없다. 삭제 요청의 범위, 같은 입력에 대한 부호 있는 기능 기여, 실제 FU 결과를 연결하는 검증이 필요하다.

가장 유망한 차별화 후보는 **삭제 요청의 기여를 검증하고 기능적 위험과 역할을 함께 추정하는 것**이다. BadFU FUBA에는 강화 억제 관계를, FedUBA에는 제출한 삭제 내용과 과거 학습 내용의 일치 여부를 검사하는 서로 다른 관측이 필요하다. 단순히 언러닝으로 백도어를 노출하거나 FL 이력을 이용하는 것은 이미 선행연구가 있다. 이는 제안 가설이며 현재 신규성이 입증된 완성 방법은 아니다.

이번 실행은 기존 모델을 다시 학습하지 않고 저장된 가중치와 마지막 라운드 제출을 읽어 수행했다. 연구 설계와 실행 프로토콜을 먼저 저장한 뒤 탐지 점수를 계산했다. 보정 패치는 공격 구성 3개 중 2개에 경보를 냈지만 보정 외 정상 실행 2개 중 1개에도 경보를 냈다. BadFU 분리형의 두 역할 순위는 맞았지만 고정 임계값에서는 미판정이었고 FUBA 역할은 잘못 지목했다. [체크포인트 실험 결과](RESULTS_KO.md)

## 1 공격 이름과 실제 저장된 모델

**FedUBA와 FUBA는 서로 다른 연구다.** 현재 로컬 체크포인트의 두 번째 계열은 `stcebra/FUBA`다. 이를 `ity207/FedUBA`의 재현이라고 부르면 안 된다.

| 연구 | 핵심 구조 | 이번에 사용할 저장 모델 |
|---|---|---|
| BadFU | 독성 P와 위장 C를 학습한 뒤 C를 삭제해 억제를 제거 | 정상 clean5, 혼합 cover5, 분리 full6, 기존 FU 결과 |
| FUBA | Adv-attacker가 주입하고 Adv-defender가 억제하다가 자신의 기여를 삭제 | 공격 시드 42와 정상 시드 42 43 44의 마지막 라운드 |
| FedUBA | STG 트리거 생성 SSS 민감도 선택 BEA 요청 특징 조작을 통한 삭제 시점 공격 | 대응하는 학습 체크포인트는 이번 선택 집합에서 확인되지 않음 |

BadFU 본문의 한 참여자 내부 샘플 삭제와 저자 코드의 분리형 참여자 삭제도 구분한다. `cover5`에서는 공격자와 위장자가 같은 ID일 수 있다. `full6`은 역할을 나눈 구현이므로 서로 다른 ID로 채점할 수 있다. 이 차이는 [기존 궤적 재사용 판정](../01_reproduction/TRAJECTORY_DECISION.md)과 체크포인트 프로토콜에 기록돼 있다.

FUBA의 Adv-defender는 공격을 함께 구성하는 억제 역할이다. 정상적인 방어자를 의미하지 않는다. [BadFU 원문 IV V절](https://arxiv.org/html/2508.15541v1) · [FUBA 저자 구현 설명](https://github.com/stcebra/FUBA) · [FedUBA 저자 코드](https://github.com/ity207/FedUBA)

## 2 두 단계가 답해야 하는 질문

### 1단계 공격 여부와 삭제 후 위험

서로 다른 정답을 함께 보고한다.

1. **공격 구성 여부**: 학습에 P C 또는 악성 업데이트가 포함됐는가.
2. **현재 기능적 위험**: 지금 실제 공격 입력에 ASR이 높은가.
3. **요청별 활성화 위험**: 같은 pre 모델에서 이 요청을 처리하면 무삭제 대조보다 ASR이 증가하는가.

현재 공격이 드러난 실행의 탐지 성공을 잠복 활성화 예측 성공으로 계산하지 않는다. 삭제 전후 위험은 `post ASR`, `post−pre ASR`, `post−matched no-delete ASR`로 각각 평가한다. ASR과 실제 타깃 트리거는 평가자에게만 허용한다. 공격자의 의도와 실제 위험도 서로 다른 정답이다. 정상 참여자의 삭제도 공격 모델에서 위험한 변화를 만들 수 있다.

### 2단계 공격자와 위장자 식별

출력은 참여자별 **강화 점수**, **억제 점수**, **역할 미확정 사유**다. 공격자와 위장자를 반드시 서로 다른 ID로 나누지 않는다. 참여자 내부 P C는 샘플 또는 독립적인 삭제 효과가 관측되는 조건에서만 채점한다. 요청자 ID를 프로토콜에서 읽는 것은 식별 성과가 아니다.

평가에는 역할별 precision recall, 정상 참여자 오지목, 위장자 순위, 공격자 집합 recall, 두 역할의 동시 식별을 넣는다. 추가로 1단계에서 놓친 공격까지 포함하는 전체 과정 성공률을 보고한다. 마지막 라운드에 없던 참여자는 그 라운드만으로 찾을 수 없으므로 전체 역할 수와 관측 가능한 역할 수를 함께 분모로 쓴다. FedUBA에는 별도 위장자가 필수가 아니므로 위장자 식별을 필수 정답으로 강제하지 않는다.

## 3 어떤 조건이 어려운가

| 어려운 조건 | 1단계가 어려운 이유 | 2단계가 어려운 이유 | 필요한 확인 |
|---|---|---|---|
| 삭제 전 강한 잠복 | 최종 모델의 ASR이나 일반 정확도에 공격이 드러나지 않음 | P C가 합쳐져 정상 기여처럼 보임 | 같은 요청의 실제 FU 전후와 무삭제 대조 |
| 강한 non-IID | 정상 삭제도 클래스별 출력과 특징을 크게 바꿈 | 정상 소수 클래스 참여자가 강화 또는 억제로 오지목됨 | 클래스 편향 저손실 고손실 삭제 대조 |
| 같은 참여자 안의 P C | 개별 참여자 제외로 C만 삭제할 수 없음 | ID 하나의 순기여에서 두 내부 역할을 복원하기 어려움 | 샘플 범위와 현지 검증 또는 독립 삭제 효과 |
| 보안 집계로 합계만 공개 | 개별 기여 비교를 계산할 수 없음 | ID별 책임이 관측에서 소실 | 허용 정보별 식별 가능 범위 제시 |
| 낮은 참여율과 역할 분산 | 현재 라운드에 억제 역할이 없을 수 있음 | 빠진 ID를 최신 제출만으로 순위화할 수 없음 | 요청 시점까지의 이력과 참여 마스크 |
| 입력 의존 또는 분산 트리거 | 작은 고정 패치 후보군이 공격 방향을 놓침 | 엉뚱한 패턴과 클래스에 대한 역할을 선택 | 같은 예산의 국소 전체영상 탐색 비교 |
| 근사 FU와 BN 변화 | 삭제 오차나 보정만으로 출력이 바뀜 | 기능 변화가 특정 참여자의 독성 기여와 일치하지 않음 | 동일 FU 예산 BN 정책과 무삭제 계산 |
| FU 중 지속 악성 학습 | 사전 잠복의 해제와 새 주입이 섞임 | 과거 역할과 현재 악성 제출이 섞임 | 공격자 정직 재학습 및 지속 공격 별도 조건 |
| 삭제 크기와 조합 변화 | 큰 요청일수록 정상 변화도 커질 수 있음 | 여러 정상 참여자의 합이 한 위장자처럼 보일 수 있음 | 크기 클래스 구성을 맞춘 요청과 조합 대조 |
| 정상 기준 자료 부족 | 보정 집합에 맞춘 낮은 오탐만 관측 | 순위가 높다는 이유만으로 역할을 강제 | 독립 정상 실행과 미판정 출력 |
| 학습 조작 없는 FedUBA | 과거 FL에서 강화 억제 쌍이 없을 수 있음 | 별도 위장자를 찾는 문제 자체가 성립하지 않을 수 있음 | 요청의 과거 자료 일치와 실제 효과 검증 |

**가장 어려운 목표 조건**은 낮은 사전 ASR, 강한 non-IID, 같은 참여자 내부 P C, 비공개 데이터, 모르는 트리거, 제한된 이력의 동시 조건이다. 우선 참여자 분리형에서 방법의 유효성을 검증하고, 혼합형에는 필요한 추가 관측을 명시하는 단계적 연구가 현실적이다.

## 4 식별 가능성의 한계

다음은 이 보고서의 간단한 관측 동치 논증이며 신경망 성능 정리가 아니다. 서버가 한 라운드에서 합계 `a uP + b uC`만 보면 임의의 벡터 v에 대해 `uP′=uP+v/a`, `uC′=uC−v/b`는 같은 합계를 만든다. a b가 양수일 때 그 두 내부 구성을 합계만으로 구별할 수 없다. 같은 참여자의 한 제출 안에 P C가 섞인 경우에도 순기여만으로 내부 분해가 유일하지 않다.

개별 제출을 볼 수 있다는 추가 가정은 ID별 기능 분석을 가능하게 하지만 악의를 자동 식별하지는 않는다. 정상 학습도 같은 패턴 방향을 강화하거나 억제할 수 있다. 그러므로 출력은 기능 역할 후보와 신뢰 범위로 제한하고, 실제 위험과 정상 오지목을 추가 검증해야 한다.

또한 마지막 제출분을 제외하고 남은 가중치를 재정규화한 모델은 **과거 전체 기여를 삭제한 FU 모델이 아니다**. 참여자 제외는 최신 집계의 기능 민감도 검사다. 이를 실제 샘플 언러닝의 결과로 해석하지 않는다.

### 원문에서 직접 확인한 부분

**UBA-Inf와 BadFU**: 위장 후 삭제 활성화는 기존 공격 기제다. BadFU V절의 P C 구성과 VII G절의 방어 실험을 두 탐지 단계의 문제 정의에 연결한다. 논문이 시험한 Median Trimean Neural Cleanse의 결과와 우리 패치 실험은 서로 다른 구현과 조건이다. [UBA-Inf 학회 원문 안내](https://www.usenix.org/conference/usenixsecurity24/presentation/huang-zirui) · [BadFU V VII절](https://arxiv.org/html/2508.15541v1)

**FedUBA**: 저자 홈페이지의 링크를 통해 원문을 확보했다. III절과 V절은 학습 중 P C 주입 대신 삭제 단계 조작을 다룬다. STG는 공개 대리 자료로 타깃 방향의 제한된 교란 δ를 만들고, SSS는 두 질의의 출력 차이 `s_i=||f(x_i+δ)−f(x_i)||`로 민감한 로컬 샘플을 선택한다. BEA는 라벨을 유지하고 삭제 입력을 `x_i′=x_i−δ`로 바꾼다. 별도 위장자가 필수인 구조가 아니다. Fig 9는 FLAME MASA의 방어 강도에 따른 잔존 ASR도 평가한다. 따라서 “기존 방어는 전부 실패한다”거나 “모든 FU 공격에 강화 억제 쌍이 있다”고 쓰면 안 된다. [FedUBA III V절 식 6 8 및 Fig 9](https://www.chenwang.net.cn/publications/FedUBA-TDSC26.pdf) · [코드](https://github.com/ity207/FedUBA)

**MASA**: 4절은 로컬 업데이트와 평균 업데이트의 융합, 정상 자료의 individual unlearning, 누적 손실 기반 필터링을 제시한다. non-IID를 다루는 방법이 이미 포함돼 있으므로 “정상 자료로 언러닝해서 이상을 찾는다”나 “non-IID를 보정한다”를 독립 기여로 삼을 수 없다. 우리 해석으로는 위장자가 정상 기능을 회복하는 방향을 제출하는 경우 강화 역할과 동일한 이상 기준으로 잡히는지는 추가 실험이 필요하다. [MASA 4절](https://arxiv.org/html/2411.01040v1)

**BackdoorIndicator와 FLAME**: 전자는 학습 전에 OOD 지표 작업을 넣는 능동 관측, 후자는 집계 방어다. 저장된 끝점의 사후 검사와 관측 정보가 다르다. 동일 관측 예산의 비교와 프로토콜을 바꿔야 가능한 비교를 분리해야 한다. 두 논문의 기존 공격 성능을 BadFU 위장자 식별 성능으로 옮겨 쓰지 않는다. [BackdoorIndicator 3절](https://arxiv.org/html/2405.20862v1) · [FLAME 원문](https://www.usenix.org/system/files/sec22-nguyen.pdf)

**FedREDefense EBYD UnlearnGuard**: 각각 학습으로 생성 가능한 업데이트인지, clean 기능을 지워 공격이 노출되는지, FU 업데이트가 이력 예측과 부합하는지를 본다. 우리 후보의 질문은 같은 요청이 억제를 선택적으로 없애는가이다. UnlearnGuard Theorem 1에는 강볼록성 smoothness 근사 오차 및 FL 중 모든 악성자 탐지 조건이 있으므로 잠복 공격을 자동 해결하는 보장으로 읽을 수 없다. [FedREDefense 공식 논문](https://proceedings.mlr.press/v235/xie24c.html) · [EBYD IV절](https://arxiv.org/html/2410.19427v1) · [UnlearnGuard Theorem 1](https://arxiv.org/html/2501.17396v1)

## 6 우리가 검증할 신규성 후보

### 후보 1 삭제 요청과 연결한 강화 억제 관계

**가설**: 같은 입력 변형과 출력 클래스에서 관측한 강화 억제 관계를 삭제 범위와 연결하면, 단순 갱신 크기나 현재 모델 검사보다 같은 정상 오경보율에서 위험 요청을 더 찾는다.

공개 정상 입력 Q와 후보 변형 τ에 대해 `B(f,τ,k)=E[p_k(f(Tτx))−p_k(f(x))]`를 계산한다. 개별 제출 제외 모델 f−i를 구할 수 있는 조건에서 `d_i=B(f)−B(f−i)`는 해당 최신 제출을 남기는 효과의 부호다. 양수는 그 변형의 클래스 k 반응을 강화하고, 음수는 억제한다. 같은 좌표에서 `P=Σ max(d_i,0)`, `C=Σ max(−d_i,0)`를 측정한다. 후보를 고르는 자료와 점수를 확인하는 자료는 분리한다.

요청 U가 억제 기여를 제거하고 강화 기여를 남긴다는 관계가 핵심이다. 이번 파일럿의 `min(P,C)`는 역할 쌍을 찾는 제한된 상쇄 기준선이며 요청별 미래 위험 예측기는 아니다. 전체 제안은 같은 요청의 실제 FU와 연결해야 성립한다. 반증 기준은 정상 non-IID에서도 같은 신호가 빈번하거나 실제 FU 위험과 관계가 없는 경우다.

### 후보 2 관측 해상도에 맞춘 두 역할 식별

**가설**: 이력의 공통 변형과 클래스에서 강화 억제의 방향과 안정성을 함께 요구하면, 독립 이상 점수 순위보다 정상 오지목을 줄이면서 두 역할을 동시에 찾는다.

최근 한 라운드 전체 이력 마지막 모델을 동일 계산 예산에서 비교한다. 역할별 정답은 점수를 저장한 후 평가자가 붙인다. BadFU 혼합형에서는 `P/C 내부 분리 불가`를 허용하고, FUBA 분리형에서는 공격자 집합과 위장자 ID를 평가한다. 실제 타깃을 모르는 상태의 역할 정확도와 실제 타깃 좌표에서만 가능한 오라클 정확도를 구분한다. 둘이 다르면 타깃 탐색 실패와 역할 추정 실패를 분리할 수 있다.

### 후보 3 정상 삭제를 기준으로 한 선택적 경보

**가설**: 삭제 크기 클래스 손실 난도 FU 예산을 맞춘 정상 대조와 미판정을 도입하면, 최대 패치 반응이나 노름 비율의 정상 오탐을 줄인다.

수치 보정 자체는 신규성이 약하다. 독립 정상 실행에서 임계값을 고정하고 새 공격 및 정상 실행에 적용하며, 미판정 비율과 탐지율을 함께 보고해야 기여가 된다. 정상 설명 가능성이 높다는 사실은 안전성의 증명이 아니다. 적응형 공격, OOD probe, 낮은 정상 자료 수, 요청 조합에 대한 실패 경계가 연구 결과의 일부다.

### 후보 4 삭제 기여의 일치성과 위험성을 분리

**가설**: 과거에 학습한 자료 범위와 독립적으로 측정한 삭제 기여의 일치 여부를 기능적 위험과 별도로 검사하면, 강화 억제 관계만 검사할 때 놓치는 요청 조작을 더 찾는다.

예를 들어 과거 자료를 서명된 ID나 검증 가능한 현지 계산에 연결하고, 허용된 삭제 집합의 효과와 제출한 삭제 효과를 비교한다. 과거 효과를 A, 요청 효과를 u라 두면 허용된 삭제 질량 q에 대해 `min ||u−Aq||` 같은 검사를 생각할 수 있다. 샘플 소유권 삭제량 클래스 선택 등 정당한 요청을 허용하는 제약이 필요하다. u를 A에서 합성해 잔차가 작음을 보이는 것은 검증이 아니며 독립적인 요청 효과가 있어야 한다. 이 설계는 저장소에 이미 있던 intra 가설을 연구 범위에 다시 연결한 것으로 이번에 새로 발명한 방법으로 주장하지 않는다.

일치한다고 안전한 요청은 아니다. BadFU의 실제 C 삭제는 과거 자료와 일치하면서 위험할 수 있다. 반대로 정상 클래스 선택 삭제를 평균 요청에서 멀다는 이유로 위조라고 판정하면 안 된다. 이 두 축을 분리하고 필요한 추가 정보를 명시하는 것이 FedUBA까지 다룰 때의 차별화 후보다.

**논문 주장 후보**: 서버가 실제 관측할 수 있는 삭제 기여의 일치성과 기능적 위험을 분리하고, 가능한 해상도에서 강화 억제 역할 또는 요청 조작 주체를 추정한다. 이 주장을 채택하려면 실제 FU 대응쌍, 독립 시드, 근접 선행방법, 구성요소 제거 실험이 모두 필요하다. 이번 최신 제출 제외 점수만으로는 이 주장 전체를 검증하지 못했다.

## 7 저장 체크포인트 실험의 고정 설계

**가설 1**: 정상 입력 변화로 보정한 패치 민감도는 정상 보정 실행보다 공격 구성 실행에서 크다.

**가설 2**: 같은 변형 클래스의 부호 있는 최신 제출 기여는 분리형의 실제 주입 억제 역할을 일치하게 순위화한다.

조건은 CIFAR-10 기존 체크포인트 7개, 학습 시드 계열당 공격 42 하나, 정상 BadFU 42 하나와 FUBA 42 43 44다. 공개 probe는 이전 탐지 선택 확인 평가에 사용한 720장을 제외한 test 이미지에서 새 시드로 클래스별 선택 8장 확인 8장 총 160장을 정한다. 고정 패치 32개와 클래스 10개를 사용한다. 각 타깃과 같은 정답 클래스는 해당 클래스 점수의 평균에서 제외한다.

서버 입력은 모델 가중치, 마지막 라운드의 제출과 가중치, 공개 정상 probe와 라벨이다. 실제 트리거 생성기 공격 타깃 역할 ID ASR 사설 샘플은 점수 계산에 쓰지 않는다. 정상 실행 42에서 계열별 임계값을 정하고 공격 구성 및 FUBA 정상 43 44에 적용한다. 같은 기존 모델의 재검사이므로 새 독립 학습 검증은 아니다. FUBA 원본 공격 코드가 test 자료를 탐색에 사용한 이력도 있어 새 probe를 공격 선택과 독립인 완전한 holdout이라고 부르지 않는다.

| 검사 | 이번에 할 계산 | 결과 해석 |
|---|---|---|
| 원점수 기준선 | 참여자별 패치 좌표를 선택 자료에서 고르고 확인 자료의 최대 점수 | 현재 최신 제출의 이상 신호 |
| 보정 기준선 | 원점수를 선택 자료의 전체 참여자 clean TV RMS로 나눔 | 정상 전체 변화에 대한 상대 민감도 |
| 상쇄 후보 | 같은 좌표의 양 음 기여 중 작은 합을 선택 확인 | 분리된 강화 억제 공존 여부 |
| 역할 후보 | 상쇄 좌표의 부호가 선택 확인에서 일치하는 ID 순위 | 해당 패턴의 기능 역할이며 악의 확정 아님 |
| 기존 실제 FU 참고 | full6와 fu_remove5 및 cover5와 fu_remove1의 점수 | 대응되는 기존 FU에 한정한 사후 검사 |

정상 보정 최대값 초과를 경보로 쓰며 5% 모집단 FPR 보장은 주장하지 않는다. BadFU 정상 독립 평가 시드가 없어 일반화 오탐률을 계산할 수 없다. 48개 제출 제외 비교는 48개의 독립 학습이 아니다. BadFU 혼합형의 위장만 삭제하는 실제 FU 대응쌍을 최신 제출 제외로 대체하지 않는다.

반증 기준은 공격 누락, 정상 43 44의 경보, 실제 역할과 부호 순위의 불일치다. 실패가 나오면 탐지 조건을 좁히고 같은 결과를 본 뒤 임계값이나 타깃을 바꾸지 않는다. 결과의 실험 단위와 정확한 분모를 [실측 결과](RESULTS_KO.md)에 남긴다.

## 8 다음 검증의 우선순위

1. **같은 요청의 실제 FU 대응**: BadFU C만 삭제 P만 삭제 정상 삭제 무삭제를 같은 출발점과 예산에서 비교한다. FUBA는 저장된 FL 분할을 그대로 사용한다.
2. **새 시드에서 임계값 고정 검증**: 정상 실행 수를 늘리고 역할 순위와 전체 과정 성공률을 실행 단위로 평가한다. 5% 수준의 exchangeability 기반 rank 검정을 원한다면 최소 비영 p값이 `1/(n+1)`임을 고려해 적어도 19개의 독립 정상 보정 단위가 필요하다. 이 표본 수만으로 정확한 FPR을 추정한 것은 아니다.
3. **근접 선행방법**: MASA, Neural Cleanse, 최근 한 라운드 점수, 전체 이력 HRAC, 갱신 크기, 정상 정확도 및 클래스별 손실을 비교한다. BackdoorIndicator는 사전 지표 삽입을 허용하는 별도 프로토콜 조건으로 둔다.
4. **신규성 제거 실험**: 요청 연결 제거 부호 제거 이력 제거 정상 보정 제거 미판정 제거를 하나씩 바꾼다. 같은 오경보율에서의 이득과 계산비용을 보고한다.
5. **실패 경계**: 혼합형 보안 집계 적응형 트리거 다수 위장자 내부 샘플 요청으로 확장한다. 역할 쌍을 전제하지 않는 FedUBA도 독립 재현해 범위를 검사한다.
