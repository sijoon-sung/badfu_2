# BadFU 코드의 첫 검증

대상은 보존된 [upstream badfu.py](../../../upstream/badfu.py)와 [준비 스크립트](../../../upstream/prepare_data.sh)다. 출처는 [저자 저장소](https://github.com/BingguangLu/BadFU)다. 파일 해시는 [검증 결과](code_contract_results.json)에 고정했다. 함수 정의만 분리해 CPU로 검사했으며 상위 학습 코드는 실행하지 않았다.

## 코드의 자료와 실행 흐름

```text
독성 데이터와 교란된 위장 데이터 로드
  → 기본 정상 5클라이언트 분할
  → clean5 / 독성 포함 bd5 / 한 클라이언트에 독성 위장 포함 cv5
  → 독성과 위장을 두 참여자로 나눈 full6
  → 저장 이력을 이용한 추가 위장 참여자 삭제와 별도 정상 참여자 삭제
```

`ul_client_datasets`는 정상 client 0 데이터를 두 참여자에서 사용한다. 따라서 한 참여자 내부의 위장 샘플만 지우는 본문 조건과 다르다. `prepare_data.sh`는 UBA-Inf 위장 교란을 실행한다. 로컬 학습 배치는 64를 직접 사용하며 상단 변수 32와 구분한다. 모델 몸통은 ImageNet 사전학습을 사용하되 입력 합성곱과 분류층은 교체된다.

## 이번에 직접 확인한 항목

| 항목 | 위치 | 작은 입력에서 확인한 결과 | 해석 |
|---|---|---|---|
| 일반 집계 | fed_avg 245행 | 가중치 0·2, 자료 수 1·3이면 1.5 | 표본 수 가중 평균 |
| FU 보정 | unlearning_step_once 460행 | 같은 크기 정보를 쓰지 않아 예제의 보정 길이는 1.0 | 일반 집계와 다른 가중 방식. 전체 성능 영향은 별도 |
| 0 갱신 | 488행 | 새 갱신 크기가 0이면 NaN | 실제 실행 빈도와 영향을 조사할 경계 사례 |
| ASR 분모 | evaluate_model 280행 | 주어진 2입력에서는 전체 50%, 원래 타깃 제외 0% | 함수는 loader 전체를 셈. 실제 artifact 구성 확인 필요 |

## 추가로 추적할 두 가지

`old_GMs`는 학습 라운드 후 모델을 append한다. FU 초기값은 `old_GMs[0]`, 호출의 과거 기준 모델은 `old_GMs[r+1]`다. 각 로컬 모델을 만든 라운드 시작점과 정확히 대응하는지 확인해야 한다. 인덱스 관측만으로 공격 결과가 무효라고 단정하지 않는다.

준비 마지막의 삭제·이동 명령과 저장 이미지 경로의 관계도 확인한다. 현재 단계에서는 저자 코드와 수정 실험의 원본을 분리하며, 발견한 차이를 조용히 고친 뒤 같은 재현이라고 부르지 않는다.

실행: 기존 실험 환경에서 `python research/01_reproduction/badfu/verify_code_contracts.py`. 결과의 B01–B04는 함수 검사이고 F01–F03은 FUBA 검사다. 이 검사는 공격 재현이나 FU의 망각 인증을 뜻하지 않는다.
