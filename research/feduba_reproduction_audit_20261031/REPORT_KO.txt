가설: 공식 FedUBA 배포본이 논문의 공격을 재현할 수 있는 일관된 실행 경로와 표본 정체를 제공한다.
관련 R03/R01/R02/D02/D06/D07/D08/D15/D18/D19/N02. 2026-10-31 KST.

결론: 아직 FedUBA를 논문대로 재현했다고 할 수 없으며, 현재 모델을 탐지 실험의 검증된 FedUBA 양성으로 사용할 수 없다. 이번에는 실제 공격 학습이 아니라, 그 전에 필요한 공식 배포본 확인과 원본 함수의 DISLAB CPU 실행 검증을 완료했다.

실제로 확인한 것
1. 저자 홈페이지의 논문 PDF(17쪽, DOI 10.1109/TDSC.2026.3703139)와 코드 ZIP을 DISLAB에 확보했다. 논문 각주의 ity207/FedUBA와 저자 ZIP의9파일이 고정 commit 005959ab8a955f4dcf094930ce6953af8fee827b의 Git blob에 모두 정확히 일치했다. stcebra/FUBA와 명확히 다른 연구다.
2. 공식 ZIP에도 필요한 utils.py와 models가 없다. 변경하지 않은 main/trigger 모듈의 두 import를 격리 프로세스에서 실제 시도했으며 각각 해당 모듈 부재로 종료1이었다. 핵심 poison_image/poison_image_label과 ResNet18_201 등의 정의가 없어 학습/평가 의미를 추측 없이 완성할 수 없다.
3. 원본 high_sensitivity_sort 함수를 AST로 그대로 분리 실행했다. 민감도 순위가 정확히 알려진 합성32샘플에서 호출부와 같은 batch1/shuffle=True의 반환 ID 순위는 정답 위치와0/32 일치했다. shuffle=False 양성 대조는32/32였다. 실제 logit 민감도 정렬은 맞지만, 섞인 순회 위치를 원 데이터셋 ID로 쓰는 것이 문제다. 실제 데이터의 오류율이나 공격 성능을 측정한 것이 아니다.
4. 원본 Arguments/merge_client_subsets를 합성 소유권 ID로 실행했다. 실제 FL/FU 공격자 client5/7과 보조모델 자료 helper의 client2/3이 다르다. 실제 다른 참여자의 개인 자료를 읽거나 유출을 관측한 것은 아니다.
5. 논문 Algorithm1/식5~8, 설정과 TableII를 코드 경로와 대조했다. 공통 가산 노이즈의 STG/SSS/BEA 큰 구조는 보이나, BEA 부호·clip·레이블 등은 빠진 utils 때문에 검증 불가다. 고정10참여자 대 라운드별 무작위10, CIFAR10 train50000/각2500 대 원문 각3000, 평가 배수와 정규화 좌표, pre-ASR 대 benign-FU ASR-B의 비교 차이를 별도 기록했다. 상세는 CODE_PAPER_MATRIX.txt.

사전 고정과 실행
PROTOCOL.txt와 audit_feduba.py/FREEZE.json을 기존 PR의 commit 23159e615cd19e8d6b93c569c1110206da9ca2df에 먼저 게시한 뒤 실행했다. DISLAB D:/FEDUBA_REPRO_AUDIT_20261031, CPU only, Python3.12.10/PyTorch2.7.1+cu118, 실제 PID25088, 원본 함수/표준 라이브러리/torch만으로 검사했다. audit exit0은 예상된 결함을 확인한 감사의 정상 종료이지 upstream 학습 성공이 아니다. 전체 trace/해시/순회-ID/순위는 RESULTS.json. 완료된 runner는 STARTED.json의 exclusive 생성으로 재실행을 막는다.

모델 보유 여부의 정확한 범위
기존 카탈로그에는 FedUBA case가 없다. DISLAB D:/와 antigravity 폴더의 이름 기반 제한 탐색에서도 별도 FedUBA 경로를 찾지 못했다. 제외 폴더와 경로 오류가 있어 모든 디스크 파일의 부재를 증명한 것은 아니다. tensor 내용을 열어 출처를 인증한 검사가 아니다. 기존 FUBA v2-v7 모델은 FedUBA로 재명명하지 않았다.

탐지 적용 가능성
FedUBA는 BadFU와 별도 공격·FU 경로를 검증하는 확장 대상으로 타당하다. 그러나 재현되지 않은 공격을 양성으로 넣으면 탐지 성공/실패 모두 해석이 무너진다. 현재 공통 탐지의 긍정 증거는 없다. 먼저 코드/자료 적격성, 실제 공격과 benign-FU 대조, 큰 정상 non-IID 삭제 순으로 통과해야 한다. D08 공격0.75848이 정상0.75525/0.76188 사이였던 반례와 D15 추가 시드 반례는 여전히 미해결이다. 재현 통과 자체도 이 반례를 해결하지 않는다. 행동 관측/독립 정상 보정 근거가 없는 새 탐지 실행은 보류했다. 다음 진입 조건과 현재 가능한 논문 문장은 DETECTION_GATES.txt.

중단 지점과 남은 일
공식 원본 재현의 G0/G1에서 필수 정의 부재와 ID 계약 실패를 확인해 대규모 학습 진입을 중단했다. 원본에 임의 utils/모델을 채우거나, 순위·소유권·설정을 조용히 수정하여 “논문 그대로”라고 하지 않았다. 필요한 전체 정의와 각 설정의 출처를 확보하거나, 차이를 명시한 별도 수정 profile이 있어야 실자료 FL/FU로 나아갈 수 있다. 자체 ASR/CA/탐지율은 이번에 생성하지 않았다. 과거 FUBA 유한 작업/모델/기본값은 불변이며 다른 GPU 작업을 종료하지 않았다.

운영상 기록
초기 PDF 텍스트 stdout에 cp949로 표현할 수 없는 문자가 있어 출력만 실패했다. UTF-8을 지정했고 원문 PDF는 불변이다. PDF 읽기용 격리 target의 최신 패키지 설치가 PowerShell stderr 처리와 의존성 충돌 경고로 중단되어 보존했다. 별도 reader_pinned에 PyMuPDF1.26.5/no-deps를 설치해 원격 렌더링을 완료했다. 전역 학습 환경은 수정하지 않았다. 이름 탐색의 첫 inline 명령은 인용 오류로 실행 전 실패했고 파일형 inventory_assets.py로 대체했다. 감사 runner와 upstream은 수정/재실행하지 않았다. 세부 완료/해시·색인 검사는 FINAL_CHECKS.json을 따른다.
