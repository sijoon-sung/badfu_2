## FUBA에서 고친 동작

1. 생성기를 학습한 작업자만 새 가중치를 갖던 흐름을 수정했다. 해당 클라이언트의 분류·억제·gamma 탐색 전에 세 작업자에게 같은 생성기를 전달하고 해시를 기록한다.
2. 생성기는 분류기 학습과 gamma 평가에서 평가 모드를 사용한다. `no_grad`만 적용해 BN 통계가 계속 바뀌던 문제를 막는다.
3. 정확도·ASR 평가는 분류기와 생성기의 모든 하위 모드를 보존·복원하며 BN을 갱신하지 않는다. 원 코드의 분류기 모드 누수와 생성기 BN 변경은 회귀 검사에서 직접 재현했다.
4. 생성기 최적화 동안 고정 분류기 매개변수의 기울기를 만들지 않는다. 생성기로 가는 입력 기울기는 유지한다.
5. 저장한 집계 생성기와 같은 생성기로 ASR을 평가한다. 기존 마지막 개별 생성기·학습 모드 평가와 숫자를 같은 조건으로 취급하지 않는다.

원본145개 소스와 기존 실패 모델은 수정하지 않았다. 새 실행은 DISLAB `D:/CONTINUATION_20261023` 아래에 별도로 저장한다. 기존 v1의 gamma·L2·방어 벡터 수정은 후보 선택으로 유지하며 저자 공인 구현 또는 논문 전체 재현이라고 표시하지 않는다. 위 오류만이 과거 약99% ASR의 유일한 원인이었다고 결론내리지 않는다.

조건: 원래 CIFAR10 분할·20개 역할·네이티브5-rank MPI를 사용했다. 실행 검사는 CPU, 클라이언트당8장,1R, 단축된 역할 루프를 썼다. 본 검증 후보는100R과 기존 전체 데이터·역할 루프를 사용하며 GPU를 BadFU와 공유하지 않는다.

비교: 원 코드 평가의 상태 변경을 직접 재현한 뒤 수정 평가의 무변경·모드 복원·라벨 보존·타깃 제외 분모·기울기를 검사했다. 실제 MPI에서5개 공격/억제 클라이언트마다 세 작업자의 생성기 해시가 같은지 확인했다.

결과: 로컬 및 DISLAB 회귀 검사 통과. 네이티브 MPI1R 저장·연결·참여자 집계 검사 통과, 집계 최대 오차0. 모든 저장 텐서는 유한하고 BN 분산은 음수가 아니다. 작은 검사의 정확도9.375%/ASR0%는 파이프라인 점검 값이며 공격 성능의 증거가 아니다.

판정: 구현 일관성 가설은 검사 범위에서 지지. 잠복 공격 재현은 미검증.100R 끝에서 고정된 마지막 체크포인트와 집계 생성기를 전체 시험 자료로 평가하며, 기존 기준인 사전 ASR≤10%를 넘으면 사전 억제 실패로 기록한다. 통과해도 동일 조건 정상 모델과 삭제 후 활성화 검증이 별도로 필요하다.
