실행 전 확인

기존15 CPU 회귀에 추가하여 새 IBA 결합·잡음 범위·BN 보정·기울기·전체 배치 학습·독립 optimizer·정확한γ/단계 순서의9개 CPU 검사를 로컬과 DISLAB에서 통과했다.

실제 CIFAR/GPU/MPI 사전 검사에서20개 참여자 제출,5개 악성 역할의 생성기 불변성, 완전 저장 및 집계 오차0, 엄격 CPU 로딩/출력을 확인했다. 이 검사는 별도64장/참여자·epoch1·1R·고정γ콜백의 메시지/저장 fixture다. CA10.9375%/ASR100%는 이 짧은 fixture의 숫자로 그대로 보존하며 잠복 억제 성공의 증거로 사용하지 않는다. 본100R은 고정γ콜백을 사용하지 않는다.

준비 단계에서 발견한 두 운영 문제는 GPU 실행 전에 고쳤다. 공식 저장소에 포함된 MNIST 자료를 코드 자산으로 대조하던 범위 문제와, attack/attack_dba를 함께 잡는 패치 문자열 문제다. 첫 미완성 준비 폴더와 최초 소스 패키지는 보존했다. 통과한 GPU 검사 경로는 SMOKE_VERIFIED.json을 따른다. 실제 학습 조건을 바꿔 재실행한 사건이 아니다.

실제 본 학습 프로세스와 GPU 작동,50epoch 단계의 배치 진행을 확인했다. 이후 라운드 번호는 STATE.json 문구뿐 아니라 manifest와 role_progress, 실제 프로세스가 함께 뒷받침할 때만 갱신한다.

본 실행의 첫1R 체크포인트도 저장·확인했다. SHA256은 f3c3e88f0922bdf4b8fb38b499ad2a6a83debd18dac537bc8f5fd500a31b4d1e이며, 초기 모델 연결과8명 제출의 실제 집계 오차0을 확인했다. 각 참여자가2500장으로50epoch/2000배치를 실제 수행했다. 다음2R이 진행 중인 것도 프로세스와 역할 기록으로 확인했다. 첫5R은 정상 준비 구간이며 이 첫 저장 검사를 억제 성공으로 해석하지 않는다.

루트 PROFILE.json은 재사용 방지를 위해 launch_enabled=false인 준비 템플릿으로 보존했다. 사용자의 새 실행 지시에 따라 명시적으로 생성한 attack_100R/PROFILE.json이 이 실행의 실제 고정 프로필이다. 실행 프로필·runtime·컨트롤러 해시는 READY.json과 attack_100R/protocol.json을 따른다.

후속 확인 ID fuba-v3를10분 간격으로 설정했다. 단순 진행에는 알림을 보내지 않으며 중단 또는 완료·검증·로컬 전달 때만 알린다. 과학적 실패에서 자동 재시작하지 않고 전달 검증이 끝나면 후속 확인을 종료한다.

판정과 중단

현재 판정은 실행 중/억제 미검증이다. γ0 실패, γ검색 상한 도달, 저장/집계/유한성 오류에서 중단한다. 준비 구간 후 전체10000/9000장ASR>10%가3회 연속이면 실패를 보존하고 중단한다. 오류 시 생성기와γ0 가상 모델·공격 앵커를 진단 파일로 남긴다. 실패에 맞춰 시드·강도·학습률을 바꾸거나 자동 재시작하지 않는다.

100R 완료 후 정확도>=80%·pre-ASR<=10% 및 저장 검증을 통과해도, 정상 모델 전이와 삭제 후 활성화를 별도 확인하기 전에는 승인된 전후쌍이 아니다. 정상 대조와 삭제 후 학습을 이 작업에서 자동 시작하지 않는다.

이 재현 준비는 non-IID 큰 정상 탈퇴 반례를 해결하는 탐지 방법이 아니다. R02에 새 근거를 연결하고 과거 실패를 삭제하지 않는다. 원본 소스·실패v2·FUBA63R/100R·BadFU확정본은 그대로 보존한다.
