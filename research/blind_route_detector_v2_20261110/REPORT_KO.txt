미지 입력조건 전환 탐색 — DISLAB 고정 비교 결과 (D20)

실제 트리거·생성기·실제 목표를 주지 않고 전후 모델의 전환 입력을 찾는 절차를 구현했다. 큰 정상 삭제를 포함한 BadFU의 고정 비교에서는 네 경로 제약의 추가 가치 가설을 통과했다. FUBA류 공통 탐지와 운영 공격 판정은 아직 검증되지 않았다.

관련 D02/D06/D07/D08/D13/D14/D15/D17/D19/T02/T03/R02/R03. INDEX/카드/원보고서/정정을 읽고, PROTOCOL과 source/freeze를 PR1에 먼저 게시·Git 원바이트 대조한 뒤 DISLAB에서 실행했다. 모든 이전 실패·기본 체크포인트와 오래된 finite 작업/정지 queue를 보존했다.

가설과 관측
가설은 '삭제 후 body에서 두 head 모두로 유지되는 목표전환을 요구하면, native 전후만 최적화하는 동등 예산 탐색보다 큰 정상 삭제와의 간격이 커진다'였다. 새 관측은 파라미터 norm/PCA/CKA/거리 변화가 아니라 동일 입력의 pre/post body x pre/post head 네 분류함수가 만족하는 관계다.
원본 x는 전후 모두 y, 변환 Tx는 원 pre에서 y·원 post에서 목표 t인 엄격 사건을 세었다. 목표10개와 mask/additive/conditional을 전부 탐색했다. 실제 trigger의 위치·모양·종류·실제 목표는 선택 입력이 아니었다. 변환의 의미보존은 고정 입력예산에 대한 가정이며 사람 검증을 했다고 주장하지 않는다.

비교
기존 loss=CE(post(Tx),t)+CE(pre(Tx),y).
새 loss=.5*[CE(posthead(postbody(Tx)),t)+CE(prehead(postbody(Tx)),t)+CE(prehead(prebody(Tx)),y)+CE(posthead(prebody(Tx)),y)].
분류기는 eval/frozen이며 body 두 번과 그 입력 gradient를 두 arm에 똑같이 쓴다. cross 함수는 발견 제약일 뿐 최종 증거는 원본 전후 모델이다. 모든 선택은 calibration에서만 끝내고 20개 선택 파일을 봉인한 뒤 test를 처음 평가했다. 선택 후 family/목표/예산 변경은 없었다.

고정 조건
seed20261110,400 Adam steps/family/arm, 한 초기값, 목표별2장/B20, mask질량16/그외 raw epsilon.05. 공개 CIFAR10을 fit32/cal20/test100장씩 각 클래스에서 분할했다. 세 집합은 비중복이나 같은 데이터셋이 과거 연구에 사용됐다는 한계는 남는다. 과거 D15(.04) 또는 D17와 수치를 직접 재현 비교하지 않는다. 실제 FL시드는 BadFU2개이며 10쌍을10독립학습으로 세지 않는다.
v1 중단의 영향 없는 baseline6arm은 T/Adam/RNG/400x20표본열/cal 결과를 SHA로 묶어 재사용했다. v2는54arm/21600step을 새로 수행해 총60개의 유효 최종 변환을 남겼다. 전체 gradient 비트 재생은 검증하지 않았다. 전체 주 탐색은 약508.4초였다. 다른 모델 서버와 공유한다는 새 자원 조건(.25 allocation/free4GiB)을 명시했고 관측 peak allocated355.47MiB/reserved400MiB였다. 시간 비교 성능 주장은 하지 않는다.

기존 G=185/900=20.5556%p, 새 G=274/900=30.4444%p. 개선89/900=9.8889%p.

검사와 실패 보존
실제10쌍의 strict checkpoint load/hash/payload/정규화, native head 재구성, 네 출력과 독립 head의 입력 gradient 일치, 같은모델 사건0을 통과했다. hook을 쓰지 않는 별도 native forward 검산에서20개 n/전환수/stable수/원클래스별 정수 개수가 정확히 일치했다. calibration 선택 산술도 일치했다. 모든 cal 후보를 별도로 재추론하거나 모든 gradient를 독립 재생한 검사는 아니다.
파생60 payload의 strict CPU load/모든 tensor finite/실제 Adam400step/400x20 schedule/동일 case의 두 arm·세 family 표본열 동일/변형 예산을 검사했다. 원본15 endpoint 파일 SHA와 모든 기존28case/default는 최종에도 같았고, remote에는 기존22.790% 정상 endpoint의 diagnostic 메타 항목1개만 추가됐다. 원모델 학습/수정0, 기존 FL/FU job 재실행0.
v1 교차 head 호출의 capture hook 덮어쓰기 오류를 발견해 해당 새 작업만 중단·보존했다. v2는 snapshot한 feature에 F.linear를 써서 hook을 우회하며 실제 logit/gradient 대조로 교정했다. 처음의 same-head 산술 검사만으로는 이 오류를 잡지 못했다. v1 route 수치는 근거로 쓰지 않는다.
별도로 SSH metadata 준비 중단과 두 pre-CNN resource 정지, 원 independent verifier의 빈 FUBA batch view 오류를 보존했다. 주 탐색은 반복하지 않았다. 새 verify_nonempty.py가 zero-eligible batch만 건너뛰어 전20결과를 확인했다. 원 controller의 failed 상태는 역사적 실패로 남기고 새 verifier/packet Task exit0와 FINAL_TERMINAL로 최종 상태를 판단한다.

신규성과 남은 주장
Neural Cleanse/UNICORN/FeatureRE/EX-RAY 등 입력 역산·특징 제약·교환은 선행연구다. 이번에 측정한 차이는 삭제 전후 body/head의 네 경로를 미지조건 획득에 함께 요구했을 때의 동등 예산 개선이다. 선행 scanner 전체와 비교하거나 최초성/논문급 신규성을 확정하지 않았다. LITERATURE_AND_SCOPE.txt의 원논문 링크와 좌표 gauge 반례를 함께 읽어야 한다.
두 endpoint의 공유 채널 좌표라는 white-box 가정이 있으며 독립적인 함수보존 좌표변환으로 cross 함수가 바뀔 수 있다. 원 native 증거는 변하지 않아도 탐색은 바뀔 수 있다. 동일 architecture의 이 경로를 범용 필요조건이라고 부르지 않는다.
D08의0.75848 대0.75525/0.76188, D15의7% 대8%, T02의 정당한 희귀도메인 삭제 반례는 그대로다. 이번 BadFU 대조는 retained-data 재학습이고 D08의 별도 능동FU 전체를 해결한 것이 아니다. 큰 정상 기여손실에서도 새 조건 오류는 생길 수 있다.
현재 출력은 입력조건/목표/원모델에서 재확인한 전환 증거와 calibration_required다. 고정 네 정상으로 운영 임계값·공격 확률·FPR/TPR를 정하지 않는다. 독립적이고 대표적인 정상 삭제 요청 분포의 보정, 다른 FU/architecture/성공 잠복 공격계열에서의 고정방법 검증이 남아 있다. 이 제한된 양성 결과를 지우거나 공통탐지 완료로 확대하지 않는다.
