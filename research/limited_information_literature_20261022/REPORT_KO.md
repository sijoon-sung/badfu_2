# 트리거와 역할을 모르는 서버의 탐지와 정상 참여자 삭제 대조

2026년 10월 22일 · 일차 출처 14편 비교 · 새로운 탐지 실험 결과 없음

**우리 문제의 핵심 정상 대조는 데이터가 많거나 특정 클래스·도메인 지식을 주로 제공하던 정상 참여자의 삭제다.** 그 참여자가 빠져 정확도·마진·표현이 크게 달라지는 것은 허용해야 한다. 트리거·공격 목표·위장자 ID를 모르고, 공격이 존재하는지도 모르는 서버가 이 정상 변화를 공격과 구별하는 문제로 설정한다.

선행 연구는 이 문제를 단일 이상 점수로 해결하지 않는다. 모델만 검사하는 연구, 개별 업데이트나 이력을 사용하는 연구, 참여자의 비공개 자료로 분산 검증하는 연구가 서로 다른 정보를 추가한다. 따라서 ‘clean 데이터가 필요 없는 방법’과 ‘정상 보정 모델·참여자 협조·사전 지표 삽입까지 필요 없는 방법’을 구별해야 한다.

직전의 [원인 분석](../mechanism_first_20261022/REPORT_KO.md)은 평가자가 실제 트리거와 P/C 구성을 아는 진단이다. 실제 차이가 존재한다는 근거이지만, 아래 제한된 서버 정보로 그 차이를 찾았다는 결과는 아니다. 또한 그 진단의 ‘독성 없는 동일 위장 삭제’는 큰 정상 참여자의 전체 이탈을 포괄한 대조가 아니다.

## 1 서버가 아는 정보를 먼저 제한한다

| 정보 | 최소 관측 조건에서의 취급 | 정보가 있으면 가능한 일 |
|---|---|---|
| 실제 삭제 전·후 글로벌 모델과 구조 | 기본 입력 | 모델 수준의 통계·기능 비교 |
| 삭제 요청자 ID와 삭제 단위 | 프로토콜이 알려 주는 요청 정보 | 누구의 무엇을 지웠는지 연결. 위장 역할의 정답은 아님 |
| 집계 가중치·신고 샘플 수·참여 이력 | 실제 기록이 있을 때만 사용 | 삭제 기여 크기와 정상 변동 조건을 기술. 신고 수가 실제 분포를 보증하지는 않음 |
| 개별 제출 모델 | 별도 관측 조건 | DeepSight·MESAS·RFLBAT·FilterFL의 개별 모델 필터링 |
| 과거 개별 업데이트와 글로벌 체크포인트 | 별도 관측 조건 | FLDetector 및 FLForensics 계열 |
| 서버의 라벨 있는 공개 과제 자료 | 기본적으로 가정하지 않음 | MASA와 클래스별 과제 반응 검사 |
| 참여자의 검증 자료와 검증 협조 | 기본적으로 가정하지 않음 | FLShield·CrowdGuard 방식의 분산 검증 |
| 정상 삭제 모델의 보정 집합 | 기본적으로 가정하지 않음 | 삭제 유형별 오탐 보정. 생성 비용·출처가 추가됨 |
| 트리거·목표 클래스·P/C 자료·주입자 및 위장자 정답 | 탐지 입력에서 제외 | 평가자만 ASR·역할 정확도를 계산 |
| 비공개 클래스별 장수와 도메인 분포 | 평가 구성에는 사용 가능하나 서버 입력과 구분 | 실제로 수집하지 않았다면 정상 보정의 입력으로 몰래 사용하지 않음 |

데이터가 없는 서버는 모델 가중치만으로 실제 정확도를 직접 측정할 수 없다. 연구용 시험 자료로 확인한 정확도 감소와 서버가 관측하는 통계는 다르다. 합성 입력에 대한 자신감이나 이전 모델과의 일치율도 정답 정확도 자체는 아니다.

현재 일부 보존 자료에는 마지막 라운드의 참여자 ID·제출 모델·집계 가중치가 있다. [기존 관측 코드](../stage1_20261020/run_observable.py)의 `bundle['client_ids']`, `bundle['cms']`, `bundle['weights']`가 이를 사용한다. 이 자료는 전체 학습 이력이나 실제 FU 전후 경로와 같지 않다. 연구 폴더에 정답 역할·원본 분할·공격 생성기가 함께 있다는 사실도 서버가 그것을 사용해도 된다는 뜻은 아니다.

## 2 가장 가까운 연구에서 직접 확인한 점

### FLForensics는 정상 목표 클래스 부유 참여자를 명시적으로 구분한다

[FLForensics 원문 §4.2 및 Appendix B/G](https://arxiv.org/html/2407.07221)은 목표 클래스 자료를 많이 가진 정상 참여자를 Category I, 적게 가진 정상 참여자를 Category II로 구분한다. 의심 입력을 목표 클래스로 보내는 이력 영향은 공격자와 Category I 모두 높을 수 있다. 그래서 의심 입력과 비공격 참조 입력에 대한 영향을 함께 사용한다. 참조 입력은 난수 입력으로도 평가한다.

**참고할 원리:** 큰 영향 자체보다 그 영향이 특정 의심 조건에 집중되는지 비교한다. **남는 조건:** 의심 오분류 입력을 먼저 확보하고, 개별 업데이트 이력이 있어야 한다. 원문은 의심 입력이 공격 표적인지 판별하는 확장도 제시하지만, 미지 트리거를 처음부터 찾아 주는 절차와는 다르다. 억제 역할은 주입 역할과 부호가 다를 수 있어 원 가정을 그대로 옮길 수 있는지도 검증해야 한다. 이 마지막 문장은 BadFU 구조에 대한 우리 해석이다.

### MM BD는 심한 클래스 불균형에 따른 정상 오탐을 직접 보고한다

[MM-BD 원문 §III-B 및 §VII-B](https://arxiv.org/html/2205.06900)은 clean 이미지와 트리거 없이 클래스별 최대 로짓 마진을 최적화하고 이상도를 검사한다. 우리처럼 모델만 가진 경우의 중요한 기준선이다.

원문 §VII-B1은 **심한 클래스 불균형에서도 정상 모델이 한 클래스에 과신해 오탐될 수 있음**을 실험한다. §VII-B는 클래스별 통계로 추정한 귀무분포가 부정확하면 명목 유의수준이 실제 오탐률과 다를 수 있다고 설명한다. 따라서 데이터가 많은 특정 클래스 참여자의 이탈 전후 마진 변화에 곧바로 공격 의미를 부여할 수 없다. 우리 FU 조건에서 얼마나 오탐되는지는 별도 질문이다.

### FreeEagle은 입력 자료 없이 검사하지만 판정 보정도 확인해야 한다

[FreeEagle, USENIX Security 2023 §3 및 §5.1](https://www.usenix.org/system/files/usenixsecurity23-fu-chong.pdf)은 중간층에 클래스별 가상 표현을 만들고, 다른 클래스 표현이 특정 목표로 비정상적으로 쏠리는지 검사한다. 실제 트리거를 복원하지 않으므로 패치 위치·모양을 정하지 않는 모델 검사 기준선이다.

다만 논문 성능 평가에서는 별도로 학습한 정상·공격 모델 중 30%씩으로 임계값을 정하고 나머지 모델에서 평가한다. 검사 입력이 자료를 요구하지 않는 것과 새 non-IID 삭제 환경의 판정 기준이 자동으로 보정되는 것은 다르다. 또 GTSRB 학습은 oversampling으로 클래스 수를 맞췄으므로, 이 결과를 불균형한 정상 참여자 이탈의 오탐 검증으로 대체하지 않는다.

### MASA는 정상 non IID에서도 망각 동역학이 달라진다고 본다

[MASA, WACV 2025 §4 및 Appendix 8.4–8.5](https://arxiv.org/html/2411.01040v1)은 개별 제출 모델에 clean proxy 자료로 진단 언러닝을 수행한다. 정상 non-IID 모델도 배운 클래스가 달라 망각 손실이 달라지므로, 먼저 다른 참여자의 평균 업데이트를 섞어 비교 조건을 보완한다.

즉 큰 망각 반응을 곧바로 악성으로 읽지 않는다는 점이 가깝다. 반면 우리 최소 조건에 없는 라벨 있는 proxy 자료와 개별 모델이 필요하다. 원문 non-IID 실험은 proxy가 125장에서 100장·50장으로 줄 때 방어가 약해지는 결과도 제시한다. 생성 proxy 대조는 사전 학습 생성 모델이라는 추가 자원을 사용한다. MASA의 진단 언러닝과 실제 사용자 FU도 구분해야 한다.

### FedREDefense는 BadFU에 중요한 적용 한계를 직접 명시한다

[FedREDefense, ICML 2024 §4 및 §6.1](https://xyq7.github.io/papers/FedREDefense.pdf)은 클라이언트 업데이트를 소수의 합성 데이터·라벨로 다시 만들어 볼 때의 정규화 재구성 오차를 사용한다. 다른 참여자와 비슷한지보다 ‘학습으로 만들어질 법한 업데이트인가’를 검사한다.

하지만 §6.1은 오염 자료로 실제 학습해 만든 data poisoning 업데이트를 이 방법으로 탐지할 수 없다고 명시한다. 따라서 올바른 학습 절차로 독성·위장 자료를 학습하는 BadFU를 바로 해결하는 방법으로 추천하지 않는다. 업데이트를 임의로 스케일링하거나 조작하는 공격의 비교 기준선으로 위치시킨다.

## 3 필요한 정보와 적용 범위를 비교한 표

다음은 원 방법의 요구 정보다. ‘적용 가능’은 입력이 맞는다는 뜻이며 우리 모델에서 탐지 성능이 검증됐다는 뜻은 아니다.

| 연구와 일차 출처 | 검사에 필요한 정보 | non-IID 혼동을 다루는 접근 | 우리 조건에 적용할 때 확인할 점 |
|---|---|---|---|
| [MM-BD, S&P 2024](https://arxiv.org/html/2205.06900) | 검사할 모델과 유효 입력 범위. 실제 이미지 불필요 | 클래스별 마진의 이상도 | 심한 불균형 정상 오탐을 원문이 보고. 역할 ID는 주지 않음 |
| [FreeEagle, USENIX 2023](https://www.usenix.org/system/files/usenixsecurity23-fu-chong.pdf) | 모델 내부 접근. 실제 이미지 불필요 | 클래스별 가상 중간 표현의 목표 쏠림 | 모델 검사와 임계값 보정 자원 분리. FU 및 큰 정상 참여자 이탈은 추가 검증 |
| [DeepSight, NDSS 2022](https://www.ndss-symposium.org/wp-content/uploads/2022-156-paper.pdf) | 글로벌·개별 제출 모델, 난수 입력 | 출력층의 정규화 업데이트 에너지, 출력 변화, 복합 군집화 | 클래스 집중은 정상 전문 참여자에게도 가능. 스칼라 크기 제거가 실제 삭제 효과 보정은 아님 |
| [MESAS, CCS 2023 계열 원고](https://arxiv.org/html/2306.03600) | 글로벌·개별 제출 모델 | 여러 층·통계의 검정과 반복 필터링. 참여자 간 클래스 유무·빈도 차이 평가 | 정상 다수 가정과 작은 군집 제외 논리. 정상 소수 도메인 집단 및 데이터량 편차를 별도 검사 |
| [RFLBAT, 저자 원고](https://arxiv.org/pdf/2201.03772) | 같은 라운드의 개별 업데이트 | PCA·K-means 뒤 군집 내 cosine 관계로 집계군 선택 | 주입자와 억제자의 관계가 일반 공모 주입과 다를 수 있음. 데이터 없는 군집 기준선 |
| [FLDetector, KDD 2022](https://arxiv.org/html/2207.09209) | 신원에 연결된 과거 글로벌 모델·개별 업데이트 | 참여자의 과거 이력으로 다음 업데이트를 예측 | 장기간 일정한 오염 학습은 별도 확인. 원문도 non-IID가 커지면 탐지 정확도가 떨어지는 경우 보고 |
| [FilterFL, CCS 2025](https://arxiv.org/html/2308.11333v2) | 전후 글로벌 모델, 개별 모델; 두 CGAN을 학습 | 증분 지식을 추출한 뒤 목표를 지배하는 공통 성분 분리 | 실제 이미지 없이 기능을 찾는 가장 가까운 방향. 두 모델 비교 자체는 선행. 정상 삭제로 드러난 지식도 대조해야 함 |
| [FLForensics, arXiv v2 2025](https://arxiv.org/html/2407.07221) | 의심 입력·목표, 참조 입력, 개별 업데이트 이력 | 목표 클래스 자료가 많은 정상 참여자와 공격자의 입력별 영향 비교 | 의심 입력 없는 1단계와 위장 억제 역할은 추가 문제 |
| [MASA, WACV 2025](https://arxiv.org/html/2411.01040v1) | 개별 모델, 라벨 있는 proxy 자료 | 모델 융합 뒤 진단 망각 반응 비교 | clean 자료를 허용하는 별도 관측 조건의 기준선 |
| [FedREDefense, ICML 2024](https://xyq7.github.io/papers/FedREDefense.pdf) | 개별 업데이트, 글로벌 모델, 합성 지식 최적화 | 개별 업데이트의 학습 재구성 가능성 | 원문이 정상 학습 절차를 통한 data poisoning 탐지 한계 명시 |
| [FLShield, S&P 2024](https://arxiv.org/html/2308.05832) | 참여자 로컬 검증 자료·추가 검증 보고 | 클래스별 손실 영향 LIPC로 자료 분포의 혼동 완화 | 서버 clean 자료 불필요지만 참여자 검증 협조·신뢰 관리 필요 |
| [CrowdGuard, NDSS 2024](https://www.ndss-symposium.org/wp-content/uploads/2024-233-paper.pdf) | 참여자 로컬 자료, 모델 교차 검증, TEE | 심층 표현 반응에 대한 검정과 서버의 피드백 군집화 | 기존 체크포인트만으로 전체 절차 소급 적용 불가 |
| [BackdoorIndicator, USENIX 2024](https://arxiv.org/html/2405.20862v1) | OOD 자료와 서버의 사전 지표 작업 삽입, 개별 제출 모델 | 실제 공격 조건 대신 서버가 정한 관측용 작업 사용 | 실제 트리거 불필요하지만 FL 학습 절차를 바꾸는 능동 방법 |
| [FedQUIT, arXiv v4 2026](https://arxiv.org/html/2408.07587) | 삭제 요청 참여자의 비공개 자료에서 로컬 계산, 이후 남은 참여자 복구 학습 | 자료 삭제 후 과제 보존과 유지 자료 재학습 기준에의 근접 평가 | 공격 탐지기가 아님. 삭제 후 정확도 유지와 망각 정확성·보안은 별도 평가 |

추가로 [Malicious Forgetting, INFOCOM 2026 저자 초록](https://wenwei-zhao.github.io/publication/conference-paper/3/)은 FU 중 백도어 결합과 방향 부분공간 이탈 탐지를 제시한다. 직접 관련된 추가 선행이지만 확인한 공개 내용은 초록 수준이므로, 데이터량·클래스 편향 보정이나 필요한 전체 관측 조건을 확인했다고 쓰지 않는다. 위 표의 본문 비교 14편과 확인 범위를 구분한다.

## 4 큰 정상 참여자가 빠지는 효과를 어떻게 다룰 것인가

단순 자료량뿐 아니라 다음 요인이 함께 바뀐다.

- **집계 비중:** 자료가 많은 참여자는 집계 가중치가 클 수 있다.
- **학습 기회:** 같은 로컬 epoch라도 자료가 많으면 SGD 스텝 수가 늘 수 있다.
- **희소 지식:** 적은 자료를 가진 참여자라도 유일한 클래스·도메인을 제공하면 삭제 효과가 크다.
- **누적 기여:** 참여 빈도와 학습 시점이 달라 최종 한 라운드의 크기만으로 기여를 표현하기 어렵다.
- **FU 경로:** 유지 자료 재학습과 근사 갱신, BN 통계의 변화가 서로 다른 정상 변동을 만든다.

### 고정된 한 라운드에서는 집계 비중만으로도 변화가 커질 수 있다

**가설: 제출 모델을 고정한 가중 평균에서 한 참여자 제외 효과에는 그 참여자의 집계 비중이 직접 반영된다.**

가정은 고정된 실수값 모델 벡터 `L_i`, 가중치 `a_i≥0`, `Σa_i=1`, 삭제 참여자 `a_r<1`이다. 원 집계를 `G=Σa_i L_i`라고 하면

\[
G_{-r}=\frac{G-a_rL_r}{1-a_r},\qquad
G_{-r}-G=\frac{a_r}{1-a_r}(G-L_r).
\]

첫 식을 정리하면 두 번째 식이 된다. 같은 편차 `G-L_r`에서 집계 비중이 커질수록 제외 변화의 배율이 커진다. 공격은 필요하지 않다. 판정은 **고정 제출 모델의 집계 제외에 대한 조건부 항등식**이다. 제출 모델이 달라지는 장기 재학습·실제 FU에는 이 식을 정확한 영향식으로 사용할 수 없다. 반증 기준은 위 가정하에서 항등식이 깨지는 경우다. 이를 실제 모델의 악성 판별 성능 증명으로 사용하지 않는다.

DeepSight의 NEUP는 출력 뉴런별 에너지를 총 에너지로 정규화해 전체 스칼라 크기와 클래스별 상대 구성을 구분한다. 이것은 참고할 수 있는 원리지만 정상 샘플 수로 인해 바뀐 표현·학습 경로·희소 지식을 모두 제거하는 보장은 아니다. [DeepSight §IV-B](https://www.ndss-symposium.org/wp-content/uploads/2022-156-paper.pdf)

## 5 평가에 반드시 넣을 정상 삭제

새 방법을 선택하기 전에 아래 정상 조건을 포함해 점수의 의미부터 확인한다. 표의 비공개 자료 구성은 **평가자가 정상 대조를 만드는 정보**이며, 서버가 해당 통계를 받는다는 뜻은 아니다.

| 정상 대조 | 고정하거나 대응할 조건 | 드러내려는 혼동 |
|---|---|---|
| 자료가 많은 정상 참여자의 전체 삭제 | 초기 모델, FU 방식, 총 자료량과 삭제량 기록 | 큰 기여와 정확도 감소를 악성으로 읽는지 |
| 같은 삭제량의 클래스 집중 참여자 삭제 | 삭제 샘플 수를 대응하고 클래스 중복 정도를 달리함 | 클래스 불균형과 목표 쏠림의 혼동 |
| 같은 삭제량의 도메인 전문 참여자 삭제 | 클래스 비율을 가능하면 대응하고 배경·도메인을 달리함 | 클래스 비율만 맞춰도 남는 특징 분포 이동 |
| 자료는 적지만 희소 클래스·도메인의 거의 유일한 참여자 삭제 | 자료량이 작은 조건도 유지 | 자료량으로 나눈 영향 점수의 오탐 |
| 동일 자료의 재학습 반복 및 FU의 정상 근사 오차 | 삭제 유무와 무작위성을 구분 | 학습 변동을 공격으로 읽는지 |
| 같은 모델에서 정상 참여자 여러 명을 각각 삭제 | 같은 출발 모델과 FU 방식 | 독립 학습 수와 삭제 요청 수를 구분하고 조건부 정상 분포 확인 |

샘플 일부 삭제와 참여자 전체 삭제는 별도 평가다. 감염된 모델에서 정상 사용자가 정당하게 삭제를 요청한 경우도 별도 표식을 유지한다. 이 경우 요청 의도는 정상이어도 모델 감염 여부의 정답은 양성이며, 위험한 활성화가 생겼다면 위험 경보의 양성일 수 있다. 따라서 이 사례를 깨끗한 모델 음성으로 넣거나 요청자를 곧바로 위장자로 정답 처리하지 않는다.

공격 없는 실행도 반드시 포함한다. 위장자 한 명이 무조건 존재한다는 가정으로 가장 특이한 참여자를 골라내면 정상 이탈 사례에서도 누군가를 공격자로 지목하게 된다. 역할 출력에는 판정 보류가 필요하며 정상 참여자 전체 삭제에 대한 오지목률을 보고한다.

## 6 우리 방법의 우선순위를 수정한다

### 전후 글로벌 모델만 있을 때

MM-BD·FreeEagle처럼 실제 입력이나 역할 ID 없이 계산하는 모델 검사부터 비교한다. 전·후 개별 통계와 변화 프로필을 함께 보되, 하나의 전체 변화량으로 압축하지 않는다. 검사 통계가 정상 큰 참여자 삭제에서 어떻게 달라지는지가 핵심이다.

이 조건에서 참여자별 추적을 하려면 신원과 기여를 연결하는 기록이 추가로 필요하다. 전후 두 모델만으로 FLForensics나 개별 업데이트 군집화를 실행했다고 부를 수 없다. 이것이 모델 수준 공격 탐지가 불가능하다는 뜻은 아니다.

### 개별 제출 모델이 있을 때

DeepSight·MESAS·RFLBAT을 자료 없는 업데이트 기준선으로 두고, FilterFL을 **자료 없는 기능 추출** 기준선으로 둔다. 모델의 클래스별 구성과 전체 집계 기여를 분리해 본다는 원리를 참고한다. 정상의 큰 자료량과 드문 도메인이 이상도 원인이 되는지 확인하고, 제출 이상과 실제 FU 후 위험을 별도 평가한다.

FilterFL은 현재 최소 입력에 더 가까운 기능 탐색 참고다. 다만 새로운 글로벌 모델에 드러난 기능이 정상 삭제로 생긴 재균형인지 악성 조건인지 여전히 검증해야 하므로, CGAN을 붙인 것 자체를 해결책이나 신규성으로 주장하지 않는다.

### 여러 라운드의 신원별 이력이 있을 때

FLDetector에서 참여자 자신의 시간적 기준을 참고한다. FLForensics에서는 의심 기능에 대한 기여와 참조 기능에 대한 기여를 비교하는 원리를 가져온다. 정상 클래스가 많은 참여자와 공격자를 비교한 문제 설정이 특히 가깝다.

원 FLForensics의 의심 입력과 목표를 실제 트리거로 채우면 원인 분석만 된다. 실제 탐지 경로에서는 미지 입력 탐색이나 외부에서 확인한 의심 사례로 그 정보를 얻고, 잘못 찾은 사례가 역할 오지목으로 이어지는지도 함께 평가한다. 위장자의 반대 기여와 같은 참여자 안의 P/C 상쇄는 별도 가설이다.

### 검증 자료 또는 참여자 협조를 허용할 때

소량의 라벨 있는 기준 자료를 허용하면 MASA를 비교한다. 참여자 협조를 허용하면 FLShield의 클래스별 손실 변화 LIPC와 CrowdGuard의 내부 표현 교차 검증을 참고한다. 특히 LIPC는 전체 정확도·평균 손실 하나 대신 클래스별 변화로 자료 구성의 영향을 줄인다는 점이 관련된다. 두 확장은 최소 관측 조건과 성능을 따로 보고한다.

사전 학습 절차를 바꿀 수 있다면 BackdoorIndicator의 능동 지표 삽입이 추가 선택지다. 과거에 그런 지표 없이 학습한 저장 모델에 원 절차를 소급 재현했다고 하지 않는다.

## 7 연구 가설과 신규성 후보

**가설 1: 삭제되는 정상 참여자의 관측 가능한 집계 기여와 클래스 반응 구조를 반영하면, 단순 전후 변화량보다 큰 정상 참여자 삭제의 오탐이 줄어든다.**

조건은 실제로 이용 가능한 집계 메타데이터와 모델 정보다. 클래스별 실제 장수를 관측하지 않았다면 대리 반응만 사용했다고 표시한다. 비교는 데이터량·클래스 집중·도메인 전문성 대조를 포함한 고정 정상 경보율에서 수행한다. 현재 판정은 미검증이다. 같은 경보율에서 공격 검출이 늘지 않거나 희소 정상 도메인의 오탐이 증가하면 가설을 좁히거나 기각한다.

**가설 2: 미지 기능을 탐색한 뒤 그 동일 기능의 기여를 추적하면, 트리거를 제공하지 않고도 주입 및 억제 역할 정보를 얻는다.**

조건은 개별 업데이트 또는 이력이 있는 경우로 한정한다. 실제 트리거를 사용하는 평가는 별도 진단으로 유지한다. 비교는 업데이트 크기·클래스 편향·시간적 이상도 기준선과 한다. 현재 판정은 미검증이다. 역할을 모르는 공격 없는 실행에서 오지목되거나 실제 기능을 찾은 경우에도 역할 분리가 안 되면 해당 추적식을 채택하지 않는다.

이 주제의 신규성 후보는 **한정된 서버 정보하에서, 정상 참여자의 자료량·희소 지식 삭제와 위장 억제 기여 삭제를 어떤 관측 관계로 구별하고 검증할 것인가**다. 최초 데이터 없는 백도어 탐지, 최초 전후 모델 비교, 최초 non-IID 공격자 추적이라는 주장은 위 선행 연구와 겹친다. 사용자 지적처럼 큰 정상 참여자 이탈을 포함하지 않은 분리는 충분한 근거가 아니다.

## 8 확인 범위와 기존 결과의 위치

본문 표 14편은 저자 원고·공식 학회 원문·저자 구현을 기준으로 조사했다. MESAS는 CCS 제목과 다른 제목의 저자 arXiv 원고도 사용했으며, FedQUIT는 2026년 4월 13일 v4를 확인했다. FLForensics는 2025년 10월 14일 v2다. Malicious Forgetting은 추가로 확인한 공식 및 저자 초록 수준이다. 논문별 확인 절과 추가 정보 조건은 [출처 목록](SOURCES.json)에 보존했다.

이번 작업에서는 논문별 방어 성능을 새로 재현하지 않았다. 보존 모델에서 수행한 기존 MM-BD 목적함수·정규화 프로필 실험은 [미지 트리거 결과](../UNKNOWN_TRIGGER_RUN_20261021/RESULTS.md)에 있으며, 그 변형 구현을 원논문 전체 재현과 구분한다. 기존 영향 추적 계산의 일부 진행·오류 기록도 전체 방법의 성공 또는 실패로 확대하지 않는다.

앞선 실제 트리거 진단의 수치와 체크포인트는 변경하지 않았다. 여기서는 그 근거의 적용 범위를 좁히고, 서버가 추가로 가져야 하는 정보와 정상 삭제 대조를 명시했다.
