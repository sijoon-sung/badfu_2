# BadFU 연구 이력과 방법별 실패 원인

**DISLAB의 기존 궤적·원본 결과·설정을 대조해 탐지와 정화를 분리했다.** 중요한 수정은 이력이 없었던 것이 아니라, 과거 이력 탐지에서 정상 오탐·보정·관측 단위 문제가 확인됐다는 점이다. 정식 기존 방법의 미실험과 우리 변형의 실패도 구분했다.

이번 정리는 새 FL 학습·FU 실행·모델 추론을 수행하지 않았다. 원격 문서 87개를 해시와 함께 보존하고, 10개 궤적 묶음의 파일 존재·크기와 3개 체크포인트 구조를 확인했다. BadFU·FUBA 각 한 FL 라운드의 집계도 CPU에서 검산했다. 전 라운드 가중치의 전체 검산을 새로 수행한 것은 아니다.

| 같은 84요청 | 공격 탐지 | 대조 오탐 |
|---|---|---|
| 패치 두 분기 | 11/12 | 3/72 |
| FC 노름 | 8/12 | 5/72 |
| Conv 노름 | 7/12 | 3/72 |
| FC 잔차 | 6/12 | 5/72 |
| Conv 잔차 | 6/12 | 3/72 |

같은 삭제 전 모델·자료·요청의 84건으로 맞췄다. 패치와 기울기 검사는 추가 정상 자료와 진단 계산량이 달라, 점수식 하나만의 효과로 차이를 설명하지 않는다. 기본 두 클래스 비중 20/70/90% 각 4조건이며 전체 210건의 중간 결과다. 대조 72건을 모두 순수 정상 클라이언트 전체 삭제로 해석하지 않는다.

## 실패 원인이 가장 분명하게 드러난 항목

- **FC·Conv 비율:** 같은 정상 모델·삭제 수·라벨 구성을 맞춰도 쉬운 자료 삭제에서 경보가 집중된다. 분자·분모를 36쌍에서 다시 분해했다. [원인 분석](detection/ratio.md)
- **이력 HRAC:** 한 정상 실행 기준으로 다른 정상 실행을 검사할 때 오탐이 컸다. 크기 보정의 이득은 있었지만, 정상 보정 자료를 맞추면 기존 방식보다 낫다는 결과가 남지 않았다. [원인 분석](detection/history.md)
- **정상 설명 집합:** 11건 전부 최종 점수를 내지 못했다. 미판정을 정상 탐지 성공으로 세지 않는다. [원인 분석](detection/normal_set.md)
- **정화 선택 점수:** 공격을 줄인 후보가 있어도 비정규화 선택 점수가 잘못된 후보를 택한 사례가 있다. 새 시드 검증과 사후 분석을 분리했다. [원인 분석](purification/head.md)

## 판단을 읽는 규칙

`관측`은 결과 파일, `수학`은 항등식·반례, `조건부 근거`는 대응 비교, `가설`은 아직 구분하지 못한 설명이다. `중단 명령 미확인`은 후속 기록이 없다는 이유만으로 접었다고 만들지 않았다는 뜻이다. 코드 테스트 수·이미지 반복 수·요청 수를 독립 학습 시드 수로 세지 않는다.
