# 기본 방법의 실제 실행 수준과 남은 비교

**기존 방법이 전부 실패한 것으로 정리할 근거는 없다.** 실행 결과가 있는 단순 기준선, 일부를 변형한 코드, 원문만 검토한 방법, 실행 여부를 더 확인해야 할 방법을 분리한다.

| 항목 | 현재 확인한 실행 수준 | 지금 말할 수 있는 것 | 아직 필요한 것 |
|---|---|---|---|
| 방어 없음·잔류 재학습 | 실제 저장 모델과 결과 있음 | 정화 전 기준·요청별 위험 비교 가능 | 같은 시작점·FU방법의 정상 대조를 조건별로 맞춤 |
| 라벨·손실 통계 | 최근 개발·도전 대조 실행 | 쉬운 대조의 분리와 클래스 편향·오라벨 혼동 | 새 정상 삭제와 공통 보정 기준 |
| FC·Conv·직교 잔차 | 기존16건과 새84/정상144건 실행 | 난이도 선택에 따른 오탐 확인 | 단독 공격 증거로 사용하지 않음 |
| 정상 미세조정 | 자체 구현의 소수설정 실행 | 일부ASR 감소와 정확도 손상 | 학습률·예산 범위를 정한 독립 비교 |
| 사후 자기증류 | 반응 전이와 같은절차 비교 있음 | 특정예산에서 제안보다 좋거나 나쁨 | 새시드·동일 접근정보 비교 |
| Fine-Pruning | 코드에`fine_prune` 특징제거 변형 | 원 논문 전체 재현이라고 할 수 없음 | 가지치기+미세조정의 공식/동등 구현과 정상대조 |
| Neural Cleanse | 저자 논문의 결과와 공식코드 확인. 우리 차분 역합성은 별도 | 우리 조건의 공식실패 근거는 없음 | 역합성 성공 여부와 이상치 판정을 단계별 검사 |
| SAU | 원문 확인. 최근코드에 정식비교 미수행 명시 | 우리 반응전이와 비교 필요 | 공식 구현 연결·정상자료/예산 대응 |
| UnlearnGuard·DeepSight·MASA | 원문·일부코드 존재. 검증한 결과파일과 해당 공식실행의 대응 미확인 | 실패로 분류하지 않음 | 입력권한·공격단계가 맞는지 먼저 점검 |
| Median·Multi-Krum·FLAME 과거실행 | FUBA pkl과기록에 과거결과 있음, K8/K20·완료/불완전 혼재 | 연구자료는 존재. 현재84건과 직접 합치지 않음 | 실제 집계설정·공식구성·FU/차감 평가를 연결한 원본 대조 |

실행 여부 미확인은 이번에 확인한 자료 범위의 상태다. 저장소 전체에 코드나 과거 실행이 절대 없다는 선언이 아니다. [과거 궤적 색인](../review_BadFU_defend/docs/operations/TRAJECTORIES.md)

## 이제 기본 실험을 할 때의 순서

1. **같은 체크포인트에서 평가를 먼저 고정:** 잠복 공격·일반 활성 백도어·정상 대조, 실제 FU와차감 대용, ASR 정의·정상 정확도·자료 분할을 맞춘다.
2. **가장 단순한 정화부터:** 방어 없음·정상 미세조정·사후 자기증류를 같은자료 접근·정상 변화 허용량으로 비교한다. 기존결과를 재사용할 수 있는지 먼저 확인한다.
3. **정식 기존법:** NC는 탐지, Fine-Pruning·SAU는 정화로 별도실행한다. 공식기본 예제를 통과한 뒤 우리모델을 연결해 구현문제와조건문제를 분리한다.
4. **왜 실패하는지 구분:** NC의 역합성 vs이상치판정, Fine-Pruning의가지치기 vs재학습, 자기증류의학습강도 vs선택규칙을 각각 기록한다.
5. **추가정보 소거:** 같은탐색·같은교정에서post-only, pre/post, history추가를 비교한다. 실제트리거·타깃은 채점에만 사용한다.

이 문서는 준비된 비교순서다. 이번 정리에서 이 방법들을 새로학습하거나실행한 결과로 포장하지 않는다. 실행명령과모델대응을 구체화할 때는 현재GPU작업과별도출력경로를 확인한다.
