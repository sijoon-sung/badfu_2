탐지: FC 특이값 비율과 랜덤 입력 패치 검사
2026-10-18 · codex/all-or-nothing

확인 결과
FC 최대 특이값 비율은 기존 16개 요청에서 공격·대조 범위가 겹치지 않았다. 기존 전체 노름 비율보다 간격은 조금 커졌다.
랜덤 노이즈 또는 0 입력으로 기존 패치 검사의 실제 이미지만 대체하면 공격·대조가 겹쳤다.
모두 이미 검토한 요청을 재분석한 탐색 결과이며, 독립 검증이나 일반적인 탐지 성공률이 아니다.

B. FC 특이값
동일 원본 모델의 고정 특징에서 기존 유지·삭제 자료 각각의 평균 CE 그래디언트를 계산했다.
이전과 똑같이 FC weight와 bias만 lr=.01로 한 스텝 변한 10x513 행렬 dR, dF를 쓴다.
기존 지표: ||dR||_F / ||dF||_F.
새 지표: sigma_max(dR) / sigma_max(dF).
새 지표를 계산할 때 표적 클래스나 요청의 공격 여부를 쓰지 않았다.

                      공격 4건          대조 12건           공격 최솟값-대조 최댓값
전체 노름 비율        2.3423~4.7095      .1538~2.2280         .1143
최대 특이값 비율      2.4218~4.8959      .1501~2.2562         .1656

오라벨 noise74는 전체 노름 비율1.759055, 최대 특이값 비율1.765394였다. 떨어지지 않았다.
오라벨 유지 변화의 첫 특이값 에너지 비중은98.7202%, 삭제 변화는98.0125%였다.
따라서 '오라벨 변화는 여러 방향으로 흩어지고 공격만 한 방향으로 모인다'는 설명은 이번 FC 행렬에서 지지되지 않는다.
최대 특이값 비율이 바뀌는 양은 두 분기의 집중도에 함께 달려 있다.
spectral_ratio / frobenius_ratio = sqrt(top_energy_share_R / top_energy_share_F).
클래스 라벨이 같다는 사실만으로 행렬의 rank가1이어야 하는 것도 아니다.

저장된 이전 결과에는 행렬이 없어, 같은 FC 계산을 다시 실행했다. 별도 정상 참조 자료는 쓰지 않았지만 클라이언트의 유지·삭제 학습 자료는 사용했다.
서버에서 이 두 행렬의 점수를 계산하는 단계에는 이미지가 필요 없다. 이전 원본 체크포인트 해시가 전부 일치했고 이전 비율 재현 오차는 최대2.3e-15 이하였다.
이번에는 후속 계산을 위해 fc_one_step_deltas.npz에 16쌍의 행렬을 보관했다.
특이값 제곱합과 Frobenius 노름 제곱의 일치도 확인했다.
FC와 기존 Conv는1스텝 대100스텝, 기준 자료 및 클리핑 조건이 다르다. 결과 차이의 원인을 차원의 크기로 단정할 수 없다.

A. 랜덤 입력으로 기존 패치 검사 대체
기존과 같은16개 요청의 원본·유지·삭제 체크포인트를 읽었다. 새 모델 학습은 하지 않았다.
실제 이미지, 데이터셋, 정답 라벨, 실제 공격 트리거, 언러닝 이후 모델은 읽지 않았다.
원래32개 패턴(4개 모서리 x8개 패턴)과10개 클래스를 검사했다. 입력 최적화는 하지 않았다.

Gaussian: torch.randn 원시 픽셀64개, 후보 선택·평가 입력 각64개를 서로 다른 고정 시드로 생성. 픽셀 범위로 clipping하지 않고 기존 정규화를 적용했다.
Zeros: 원시 픽셀이 모두0인 입력. 동일한0 입력64개는 하나와 같으므로1개만 사용했다. 독립 검증으로 세지 않았다.
가짜 입력에는 정답이 없어서 원래 검사에서 쓰던 '실제 정답이 후보 표적 클래스인 자료 제외'는 할 수 없다. 모든 가짜 입력에서 평균을 계산했다.
각 모델에서 패치 전후 표적 확률 차이를 계산하고, 유지 모델-원본 모델 차이가 가장 큰 패턴·클래스를 선택했다.
같은 후보에서 기존 짝 비교식 max(0,min(유지-원본, 유지-삭제))으로 확인했다.
Gaussian은 선택에 쓰지 않은 별도64개 입력으로 평가했다. 0 입력은 같은 입력으로만 계산했다.
기존 정상 이미지에서 정한.006 임계값을 새 분포의 판정 기준으로 사용하거나 다시 맞추지 않았다.

                공격 점수 범위           대조 점수 범위
Gaussian        .000596~.003064          0~.003183
Zeros           0~.111104                0~.062663

둘 다 겹쳤다. Gaussian에서 attack72=.002258, normal72=.002455였다.
Zeros에서 attack73=0, 안전 대조 delete_poison73=.062663이었다.
96.17%의 실제 미래 공격 성공률이 확인된 attack74에서도 Gaussian 선택 표적은 실제 표적0이 아닌4였다.
이는 이 고정 패턴 검사에서 이미지만 대체하는 방식이 실패했다는 결과다. 모든 합성 입력 방법이나 입력 최적화가 실패한다는 증명은 아니다.

실험 조건상 한계
기존 Conv 복제 모델은500장의 정상 기준 자료와 KL 항으로 학습됐다. 이번 A의 서버 검사만 실제 이미지0장인 것이며, 전체 기존 복제 학습 절차가 정상 기준 자료 없이 된 것은 아니다.
Gaussian 원시 값은 정상 픽셀 범위 밖에 있다. 랜덤 배경에서도 백도어가 무조건 작동한다는 보장은 없으며, 패치 효과는 입력에 따라 직접 확인해야 한다.
실제 이미지가 없는 다른 입력 합성 접근인 DeepInversion은 입력을 최적화하고 BN 통계로 중간 특징을 정규화한다. 단순 randn 대체와 다르다. 이번에는 실행하지 않았다.
