# D12 정상 이미지 없이 조건부 전환과 이력을 찾는 검사

## 실험을 시작한 이유

라벨 있는 정상 이미지를 서버가 확보해야 한다는 조건을 줄이려고, 모델에서 만든 합성 입력으로 삭제 후에만 나타나는 공통 오분류를 찾았다. 같은 기능에 요청자의 억제와 잔류 참여자의 강화 이력이 함께 있는지도 검사했다.

## 사용한 모델과 자료

처음 11쌍, 과신 완화와 정상 전체 삭제를 추가한 후 13쌍을 검사했다. 유지 자료 전체 재학습 9쌍, 저자 FedEraser 2쌍, 정상 전체 삭제의 5시점 FU 변형 2쌍을 구분했다. 자연 이미지 320장과 실제 트리거는 후보와 점수 고정 후 평가자가 사용했다.

## 실제 진행 순서

1. 클래스마다 탐색 4장과 별도 확인 4장, 총 80장의 합성 입력을 만들었다. 모델의 예측을 임시 라벨로 사용해 실제 이미지 의미를 안다고 가정하지 않았다.
2. 위치 미지 마스크와 공통 가산 변형을 찾았다. 원본은 전후 같은 클래스로 유지하고 변형 입력만 후 모델에서 공통 목표로 바꾸도록 학습했다.
3. 독립 확인에서 원본 일치 90% 이상, 비목표 클래스 중 최소 5개에서 각각 80% 이상 전환을 요구했다.
4. 첫 결과를 본 뒤 합성 입력의 과신을 줄이는 label smoothing 0.2를 추가 검사했다. 이 수정은 사후 탐색으로 표시했다.
5. 보존 시점 1·3·5에서 요청자의 억제와 잔류 참여자의 강화를 찾고 2·4에서 같은 부호가 유지되는지 확인했다. 요청자 이력이 없거나 신원이 불명확하면 역할 검사에서 제외했다.

## 결과

원래 합성과 과신 완화 조건 모두 최종 공격 경보는 0이었다. 대표 BadFU의 자동 후보는 독립 합성 입력에서 공동 전환 0%였다.

평가자가 실제 트리거를 준 경우에는 같은 대표 모델의 독립 합성 입력 36장 중 30장이 전환했다. 반면 저자 FedEraser의 과거 고사전 ASR 모델은 실제 트리거를 줘도 합성 입력 전환이 1/36이었다. 한 이력 후보는 부호 확인을 통과했지만 정상 참여자를 강화자로 골랐고 행동 조건도 통과하지 못했다.

## 결과를 보고 내린 판단

대표 모델에서는 신호가 전혀 없는 것이 아니라 자동 탐색이 유효한 조건을 찾지 못했다. 다른 모델에서는 합성 입력 자체가 공격 행동을 충분히 드러내지 못했다. 이 두 실패를 같은 원인으로 합치지 않았다. 경보가 모두 0인 결과를 낮은 오탐의 성공으로 표시하지 않았고, 이력의 부호 일치만으로 공격자 역할을 확정하지 않았다.
