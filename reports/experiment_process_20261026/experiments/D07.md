# D07 서버가 심은 진단 과제의 유지 여부 검사

## 실험을 시작한 이유

저장 모델을 관찰하는 데 그치지 않고 서버가 진단 과제를 미리 심으면 새로운 구별 정보를 얻을 수 있는지 확인했다. BackdoorIndicator의 발상을 따라, 참여자가 학습한 후 서버의 별도 과제를 얼마나 유지하는지 비교했다.

## 사용한 모델과 자료

정상 모델 복사본에 난수 이미지 200장과 임의의 균형 라벨을 사용했다. 같은 진단 모델에서 정상 균형 2,048장, 정상 편중 2,048장과 8,192장, 독성 혼합, 독성 및 위장 혼합, 억제 자료 학습을 비교했다. 실제 FU 전체가 아닌 한 번의 로컬 학습 파일럿이다. BadFU는 저장 위장 이미지, FUBA 방식은 과거 s42 생성기를 모의 참여자 구성에 사용했다.

## 실제 진행 순서

1. 복사한 정상 모델에 200 미니배치로 난수 과제를 학습시켰다. 원래 과제와 진단 과제의 BN 통계는 분리했다.
2. 같은 출발 모델에서 여섯 종류의 로컬 학습을 하고 진단 과제 유지율을 비교했다.
3. 첫 검사에서 정상 성능 손상과 한 클래스 쏠림을 확인했다. 후속 검사에는 공개 500장의 삽입 전 예측을 보존하는 증류 항을 추가했다.
4. 진단 라벨이 c인 입력의 c 예측률에서 다른 진단 라벨 입력의 c 예측률을 뺀 J를 계산했다. 모든 입력을 한 클래스로 보내면 J가 0이 되는지 검산했다.
5. 과제의 모든 클래스를 학습했는지와 정상 정확도 하락 5%p 이내를 먼저 확인한 후 점수를 비교했다.

## 결과

첫 BadFU 방식 검사에서는 정상 편중 8,192장 학습도 유지율 100%였고 독성은 95% 또는 100%였다. 과제 삽입 자체도 정상 정확도를 크게 낮췄다.

후속 FUBA 방식 두 조건은 정상 기능과 과제 학습 기준을 통과했다. 그러나 J는 정상 균형에서 0.844와 0.889, 독성 혼합에서 0.267과 0.583이었다. 정상 쪽이 더 높았다. 후속 BadFU 방식은 과제 학습과 정상 기능 보존에 실패해 탐지 성능 판단에서 제외했다.

## 결과를 보고 내린 판단

출력 쏠림 보정은 단순 한 클래스 붕괴를 제거했지만 악성과 정상의 구별을 만들지는 못했다. 추가 과제를 심었다는 사실 자체가 공격에만 반응한다는 근거가 되지 않았다. 진단 과제가 들어간 모델에서 실제로 새 제출을 계산했으며, 옛 업데이트를 더해 새 학습을 대신하지 않았다. 이번 파일럿을 실제 대규모 삭제 탐지율로 표시하지 않았다.
