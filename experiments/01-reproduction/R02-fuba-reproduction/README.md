## 최신 결과: v7 실제100R와 KD10 완료 (2026-10-28)

수신한 이전 라운드 생성기와 gamma0~1 전체11격자를 사용하는 두 변경을 선언하고, 같은 초기분류기에서 실제100라운드/800역할과 실제 참여자4 차감 후 KD10/400배치를 완료했다. 전체 CPU/정확41개기여차감/독립 동일G10000·9000 평가가 통과했고 실제 전후 모델·KD10·전체epoch로그를 양쪽에 전달했다.

전 CA77.76%/ASR10.5556%, 후 CA77.76%/ASR16.7444%로 성능 목표는 미달이다. 두 변경을 동시에 적용해 단독 인과를 분리하지 못했으며 D08 반례는 해결하지 않았다. gamma0 미달이나 양수 통과는88역할, 전체격자 미달 exact-zero는49R/client0 한 역할이었다. 전체 감마 점수를 독립 추론했다고 주장하지 않는다.

새 사례 `fuba.v7.s20261023.pre100.post.kd10`은 진단 전용이다. 로컬35개 model payload strict CPU 검사와 양쪽 카탈로그 guard가 통과했고 기존 실패와 기본값은 유지했다. 전체 중간 원시모델은 DISLAB 원본에 남아 있다. 원 근거는 로컬 보관 `research/fuba_paper_grid100_20261027/FINAL_DELIVERY_REPORT_KO.txt`, `FINAL_PAPER_COMPARISON.txt`, `FINAL_COMPLETION.json`이다.

## 실험을 시작한 이유

FUBA에서도 삭제 전 억제와 삭제 후 활성화가 재현되는 모델쌍이 있어야 탐지 방법을 공정하게 비교할 수 있다. 과거 모델은 삭제 전부터 ASR이 높았고 같은 생성기가 정상 모델에도 잘 통했다. 그 모델을 잠복 공격의 성공 사례로 쓰지 않고, 출처와 구현을 감사한 뒤 별도로 선언한 실행을 진행했다. 대상은 stcebra FUBA이며 ity207 FedUBA와 다르다.

## 공통 조건과 평가

후기 수정 실행은 CIFAR 10, ResNet18, 참여자 20명 중 라운드당 8명, 시드20261023의 고정 IID 분할을 사용했다. 분류기 학습 단계는 전체 50에포크, 생성기는 5에포크로 기록했다. 전체 정상 정확도 CA는 10,000장, ASR은 목표 클래스 8을 제외한 9,000장으로 측정했다. 전후 비교는 같은 최종 삭제 전 생성기, epsilon 0.05, pixel 0~1, eval 모드, contiguous NCHW를 유지했다.

완료 목표 100라운드, 정상 정확도 80% 이상, 사전 ASR 10% 이하, 삭제 후 ASR 60% 이상은 서로 다른 확인 항목이다. 파일 저장 검증이 통과해도 성능 목표를 통과한 것으로 표시하지 않았다. 아래 버전들은 조건 변경과 일부 구간 재사용이 있어 독립 학습 시드 반복으로 합치지 않는다.

## 초기 모델과 v2의 실제 실행

1. 과거 FUBA 쌍에 같은 저장 생성기를 적용했다. 공격 전후뿐 아니라 정상 모델에서도 높은 목표 예측이 나오는 것을 확인했다.
2. v2 수정 후보를 고정해 100라운드 학습과 저장 검사를 진행했다. 82라운드 목록 교체의 Windows 접근 거부로 멈췄지만 모델 파일은 저장돼 있었다.
3. 81→82 연결과 실제 집계를 확인하고 원본 실패를 보존했다. 저장 재시도를 보강한 별도 경로에서 83~100라운드를 이어 계산했다.
4. 최종 분류기와 같은 집계 생성기로 전체 평가하고 로컬 검토 사본을 보관했다.

v2는 100라운드를 완료했지만 CA 71.87%, 사전 ASR 99.0889%였다. 이 후보의 실제 삭제 후 분기는 실행하지 않았으며 단일 진단 모델로 남겼다. 63라운드 중간 사본과 82라운드 오류도 보존했다.

## 논문과 실행 코드를 다시 대조한 과정

1. 실제 16쪽 본문과 12쪽 보충자료를 구분했다. 본문 Algorithm1과 2, 재가중 식, 예상 집계, 실험 설정을 실행 소스와 대조했다.
2. 재가중 방향이 반대인 문제, 억제 두 번째 단계에 정상 입력 대신 생성기 입력을 넣는 문제, 학습 단계와 optimizer 상태 재사용 문제를 확인했다.
3. 예상 집계 비율, gamma 후보와 제출값 연결, 첫 실패와 상한 처리, 실제 epoch와 batch 수를 검사했다.
4. 수정 후보를 별도 디렉터리에 만들고 CPU 합성 회귀 15개를 통과시켰다. 이 단계 자체에서는 새 실자료 학습을 하지 않았다.

각 불일치는 확인했지만 어느 수정이 최종 ASR을 얼마나 바꾸는지 단독 인과 기여는 측정하지 않았다. 본문 수식의 SGD와 실험 설정의 Adam, IBA 결합과 BN 정책의 모호함도 남겼다.

## v3와 v4에서 중단된 이유

v3는 위 감사를 반영한 별도 프로필로 시작했다. 15라운드를 저장한 뒤 16라운드 참여자1의 gamma 0 예상 집계가 로컬 ASR 12.9464%, 29/224로 기준을 실패해 등록한 whole MPI 중단 규칙에 따라 멈췄다. 마지막 15라운드 전체 평가 CA 76.10%, ASR 8.1333%는 독립 평가와 일치했다. ASR이 낮아도 100라운드와 정상 성능 목표는 미달이었다.

v4는 논문의 초기 while 조건이 거짓일 때 gamma 0을 반환하는 흐름을 따르도록 별도 선언했다. 첫 15라운드는 같은 해시로 가져오고 이미 완료된 16라운드 첫 참여자의 단계만 재사용한 뒤 나머지를 학습했다. 23라운드까지 저장했지만 24라운드 참여자3에서 선언한 gamma 상한 10에 도달해 멈췄다. 마지막 전체 평가 CA 77.12%, ASR 13.9444%였다.

상한 분기는 중간 분류기와 101개 점수를 저장하지 못했다. 원본 생성기를 재사용한 한 참여자 진단을 별도로 수행했지만 gamma 2.0 통과와 2.1 실패가 나와 원래 상한 10 종료를 재현하지 못했다. 이 진단 모델로 원본 24라운드를 대체하지 않았다. 보고서의 cap2라는 오기는 gamma2.0 선택으로 정정했다.

## v5에서 100라운드와 실제 KD10을 수행한 과정

1. 1~23라운드는 원본 해시 그대로 가져오고 24~100라운드는 새로 계산했다. 위 단일 참여자 진단 모델은 넣지 않았다.
2. gamma 상한 10에서 모두 통과하면 마지막으로 검사한 통과값을 제출하고 최대값을 찾았다고 단정하지 않는 유한 정책을 선언했다.
3. 31라운드 gamma 10 제출 직후 CA 10.19%, ASR 0%로 효용이 무너졌다. 실제 제출과 집계가 저장 상태와 같은지 확인하고 원본 실패를 남긴 채 100라운드까지 진행했다.
4. 32라운드 상태 파일을 읽던 감독만 종료됐을 때 기존 학습 프로세스에 새 감독을 연결했다. 학습 재시작이나 중복 MPI는 없었다.
5. 100라운드 검증과 독립 평가를 완료했다. 다음 삭제 단계에서는 참여자4의 실제 과거 선택과 가중치로 기여를 누적해 차감했다.
6. 학생은 차감 상태, 교사는 고정된 100라운드 모델로 두고 정상 잔류 참여자5의 무라벨 2,500장으로 10회 KD, 400배치를 수행했다. 온도30, SGD0.01과 momentum0.9, 정답 CE와 T제곱 배율 없이 KL을 사용했다.

v5의 실제 전후 결과는 아래 표와 같다. 같은 생성기의 독립 전체 평가가 일치했고 양쪽 호스트에 전후 모델과 로그를 보관했다. 실제 선택 ID와 가중치, KD 10회, clean 입력, 고정 교사와 생성기는 공개 코드에서 정정한 조건으로 명시했다.

## v6에서 수식의 업데이트를 따로 검사한 과정

1. 소스를 다시 직접 실행해 가중 기울기에 Adam을 적용하는 것과 수식 그대로의 가중 SGD가 다른 갱신을 만드는 것을 확인했다.
2. 명시된 두 업데이트는 SGD, 다른 단계는 Adam으로 수행하는 해석을 새 프로필에 고정했다. 악성 비율 m은 본문 5를 유지했다. 유일한 저자 공인 해석이라고 부르지 않았다.
3. 같은 초기 모델에서 100라운드를 새로 계산하고 실제 참여자4의 41개 기여를 차감했다. v5와 같은 KD 계약으로 10회, 400배치를 수행했다.
4. 첫 정상 라운드, 첫 억제자와 첫 공격자 단계에서 실제 50에포크와 optimizer, 같은 생성기, 제출식과 집계를 검사했다. 전체 검증도 100라운드, 800역할, 186생성기 그룹과 KD 로그를 확인했다.
5. 독립 점수 확인에서 9라운드 gamma2.4가 CPU 24/220, 원래 GPU 23/220으로 한 장 달랐다. 선택 gamma2.3은 18/220으로 같았고 2.4는 양쪽 모두 탈락했다. CPU 세 계산 모드로도 원래 23건은 재현되지 않았다.
6. 감사 출력 오류는 CPU 관측기만 별도로 복구했다. 첫 같은 GPU 독립 평가 시도는 다른 앱의 GPU 점유 812MiB로 추론 전에 차단돼 실패를 보존했다. 이후 사용자의 명시적 승인으로 확인된 GPU 앱을 종료하고 유휴0MiB에서 평가·내보내기만 복구했다. 학습을 재시작하거나 유휴 기준을 바꾸지 않았다.

## 2026년 10월 27일 실패 진단과 제한 재시도

사용자의 재시도 요청에 따라 원본을 보존한 별도 DISLAB 폴더에서 실제 학습을 다시 비교했다. 논문 구현 문단의 이전 라운드 생성기·0~1 감마 격자와 v6의 새 로컬 생성기·상한10 순차 탐색 차이를 확인했다. 저장된7/client0과100/client1은 gamma0 실패 때문에 탐색을 끝냈지만, 새 독립 계산에서 양수.1~1은 모두 로컬 예상 ASR 기준을 통과했다. 조기 종료를 없앤 별도 후보는8개 CPU 검사를 통과했다. 이것이 최종 FL 성능을 고쳤다는 증거는 아직 없다.

최초 악성 역할에서 생성기 시점만 바꾼 두 조건을 각4단계50epoch, 총400단계epoch/14400batch 학습했다. 이전G 조건의 정상 정확도가67.2%에서37.6%로 무너졌고, 높은 목표 예측은 정상 이미지에도 나타났다. 사전 중간 기준에서 실패하여 전체100R를 시작하지 않았다. 최초 역할의 이전G는 아직 악성 학습 전이므로 이후 역할까지 일반화하지 않는다. 원래 방식의 재학습 역시 원본 tensor와 비트 단위로 같지는 않았으며 현재 runtime 비교라는 한계를 남겼다.10모델·optimizer/RNG·로그를 로컬 전달하고 CPU 검증했다.

원인 진단과 재시도 결과는 로컬 보관 `research/fuba_v6_failure_diagnosis_20261027/REPORT_KO.txt` 및 `GAMMA_GRID.json`, `replay/RESULT.json`을 따른다. 새 전체 실행과 재현 성공은 별도 미해결이다.

## 결과를 보고 내린 판단

v5와 v6는 실제 100라운드와 실제 KD10 후 모델을 만들었다. 둘 다 사전 억제와 강한 삭제 후 활성화라는 전체 성능 목표를 재현하지 못했다. 모델 저장과 실행 계산 검증을 성능 재현 성공으로 합치지 않았다.

이 일련의 작업은 공격 구현과 재현 검사다. D08의 큰 정상 non-IID 삭제와 공격을 구별하는 탐지 문제를 해결한 실험은 아니다. 각 버전의 원본 모델, 중단, 운영 오류, 정정과 평가 차이를 모두 남겼다.
