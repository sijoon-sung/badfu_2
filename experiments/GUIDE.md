# 용어와 모델 구분

[저장소 첫 화면](../README.md) · [전체 실험](README.md)

## 결과를 읽을 때

| 표현 | 뜻 |
|---|---|
| 위장 자료 | 공격 효과를 억제하도록 학습에 넣은 자료. BadFU 재현에서는 트리거를 넣고 원래 정답을 유지한다. |
| 독성 자료 | 공격자가 원하는 오답을 학습시키는 자료 |
| 큰 정상 삭제 | 공격 없이도 모델에 큰 변화를 만드는 정상 참여자의 자료 삭제 |
| 정상 정확도·CA | 원래 시험 이미지의 정답률 |
| 공격 성공률·ASR | 실제 트리거를 알고 있는 평가자가 측정한 목표 오분류 비율 |
| 새 목표 오류 비율 | 탐색한 변형에서 삭제 후에만 생긴 오류의 비율. 실제 트리거 ASR과 구분한다. |
| 학습 시드 | 모델 학습의 무작위 초기 조건. 같은 모델의 탐색 반복 수와 구분한다. |

## 삭제 후 모델을 만든 방법

| 방법 | 실제로 한 일 |
|---|---|
| 유지 자료 전체 재학습 | 같은 초기값에서 삭제 자료를 제외하고 학습을 다시 수행 |
| FedEraser 또는 보존 5시점 FU | 저장 이력과 잔류 참여자의 재보정으로 만든 삭제 절차 |
| 최신 제출 제외 | 마지막 집계에서 특정 참여자의 제출만 뺀 진단 |
| 복사본 수정 | 검사 목적으로 추가 학습하거나 층을 교체한 진단 |

각 실험은 사용한 방법을 본문에 명시한다. 진단용 복사본의 결과를 실제 삭제 후 모델의 결과로 합치지 않는다.

## 모델과 원본 파일

GitHub에는 과정, 설정, 수치와 검증 기록을 둔다. 대용량 모델 가중치와 학습 데이터는 로컬·실험 서버의 보관 경로를 사용한다.

- [모델 카탈로그 안내](../research/00_trajectories/README.md)에서 명시적 case ID와 허용 용도를 확인한다.
- [카탈로그 원본](../research/00_trajectories/catalog.json)에서 경로, 파일 형식과 검증 근거를 찾는다.
- [BadFU 기준 모델 안내](../CONFIRMED_CHECKPOINTS/BadFU_s20261023_v1/README.md)와 [FUBA 모델 보관 안내](../CHECKPOINTS_FOR_REVIEW/README.md)에서 보관 범위를 확인한다.

폴더가 존재하거나 파일 검사가 통과한 사실과 공격 재현·탐지 성능이 확인된 사실은 각 실험의 판단에서 따로 읽는다.
